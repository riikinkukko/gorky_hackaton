# Демо-сценарий на 3 минуты

*Реплики шагов 1–6 есть в `golden_eval.jsonl` дословно (q11, q01, q08 + q51, q10 + q53, q19, q28), шаг 7 — вариант q17 + q92. Ожидаемые ответы посчитаны по CSV организаторов. Стенд работает с `FREEZE_NOW=2026-10-21T14:00:00+03:00` (среда): на этих данных ответы известны заранее, и демо не зависит от реальной даты показа.*

---

## 1. Роли

| Кто | Что делает |
|---|---|
| **Ведущий** | говорит с ассистентом и с жюри, держит темп |
| **Оператор** | за ноутбуком: экран, кнопки «Отменить» и быстрые ответы, переключение на запасной план |
| **Страхующий** | второй ноутбук с локальной копией и открытым видео демо; следит за таймером, показывает «−30 с» |

## 2. Что на экране

Слева — диалог: кнопка «зажми и говори», распознанный текст, ответ, карточки записей. Справа — панель «Сегодня / Неделя». Шрифт крупный (проектор), звук ответа включён, громкость проверена.

---

## 3. Сценарий

Время — от начала выступления. Жирным выделены слова, которые нужно сказать дословно: под них настроены тесты.

| # | Время | Ведущий говорит ассистенту | Ожидаемый ответ ассистента | Что подчеркнуть жюри (одна фраза) |
|---|---|---|---|---|
| 0 | 0:00–0:15 | *Жюри:* «Мы загрузили ваши 1000 событий. Сегодня, по данным, среда, 21 октября. Всё — голосом, вживую.» | — | Ассистент «живой» с первой секунды, база не пустая |
| 1 | 0:15–0:30 | **«Что у меня сегодня?»** | «Сегодня у вас 2 записи: 08:00 — Встреча с Марией по презентации; 10:15 — Подготовиться к встрече с Пульсом.» | Данные организаторов, понятный ответ |
| 2 | 0:30–0:50 | **«Напомни мне завтра в 10 утра позвонить Ивану»** | «Напомню: позвонить Ивану — чт, 22 октября, 10:00.» Карточка и кнопка «Отменить» | «Дату считает код, а не нейросеть, и мы всегда проговариваем её целиком: ошибку видно сразу» |
| 3 | 0:50–1:15 | **«Поставь встречу с Иваном завтра»** | «На какое время поставить встречу?» + кнопки 10:00 / 15:00 / 18:00 | Не хватает данных — ассистент спрашивает, а не выдумывает |
|   |   | **«В три»** | «Записал встречу «Встреча с Иваном» — чт, 22 октября, 15:00.» | «В три» понято как ответ на вопрос и как 15:00 |
| 4 | 1:15–1:45 | **«Поставь созвон с Маяком 29 октября в 15:30»** | «29 октября в 15:30 у вас уже: «Передать отчёт на согласование», «Созвон с Орбитой по презентации». Поставить на 16:30 или всё равно на 15:30?» + кнопки 16:30 / Всё равно 15:30 / Отмена | Конфликт найден в ваших данных, предложено решение |
|   |   | Оператор жмёт **«16:30»** (или ведущий: «давай на 16:30») | «Записал встречу «Созвон с Маяком» — чт, 29 октября, 16:30.» | |
| 5 | 1:45–2:10 | **«Когда у меня была встреча с Иваном?»** | «Последняя — чт, 5 марта, 15:45: «Встреча с Иваном по презентации». Ещё: сб, 27 сентября 2025… пт, 4 апреля 2025…» | В CSV написано «Позвонить Иваном» и т. п. с ошибками падежей — поиск это переживает. «Была» = только прошлое: завтрашняя встреча не попала |
| 6 | 2:10–2:25 | **«Найди всё про ТЗ»** | «Нашёл [N] записей по запросу «техническое задание». Ближайшие три: … Уточнить по человеку или дате?» + кнопки «Только прошедшие / Только будущие». **Текст сверить на стенде** (в CSV 27 записей с ТЗ) | Синонимы: в данных нет слова «ТЗ». Длинный список не зачитываем целиком |
| 7 | 2:25–2:45 | **«Что у меня в субботу?»** | «В субботу три записи: 10:45 — проверить смету по мобильному приложению, 14:15 — отправить протокол Елене, 20:45 — встреча с Марией по интеграции.» | |
|   |   | **«Встречу перенеси на воскресенье в 12»** | «Перенёс «Встреча с Марией по интеграции» на вс, 25 октября, 12:00.» Кнопка «Отменить» | Контекст: «встречу» — та, что в списке выше |
|   |   | **«Отмени»** (голосом) | «Вернул как было: «Встреча с Марией по интеграции» — сб, 24 октября, 20:45.» | Отмена работает и голосом, и кнопкой «Отменить» — по одному журналу действий |
| 8 | 2:45–3:00 | Оператор переключает на слайд качества | — | «На 100 эталонных запросах — 93% сценариев целиком, 14 из 14 фраз ТЗ, интент и даты — 100%, поиск находит нужное в 100% случаев. И всё это на правилах, без LLM, за сотые доли секунды.» Цифры — `backend/eval/report.md` |

**Если опережаем график** (после шага 7): **«Отметь, что смету по мобильному приложению я проверил»** → «Отметил выполненной: проверить смету по мобильному приложению, сб, 24 октября». Затем показать в Яндекс Календаре подписку на ICS-фид `https://voice.planimetrika.online/calendar/demo.ics` (токен `demo` → демо-пользователь 1 с данными CSV).

**Если отстаём:** пропустить шаг 6, затем шаг 7. Шаги 1–5 обязательны: это четыре ключевых действия из ТЗ плюс уточнение и конфликт.

> **ICS — только как картинка «уже подписано».** Яндекс и Google обновляют подписанные календари с задержкой (от десятков минут до суток), поэтому новая встреча может не появиться на глазах у жюри. Подписку на `https://voice.planimetrika.online/calendar/demo.ics` оформляем заранее и показываем импортированные события, а не только что созданные. Если календарь не загрузился — открыть сам фид в браузере: видно, что это стандартный iCalendar.

## 4. Запасной план

Решение принимает оператор за 2–3 секунды и проговаривает переход одной фразой, без извинений.

| Что сломалось | Признак | Действие | Фраза ведущего |
|---|---|---|---|
| Микрофон или шум в зале | Транскрипт пустой или кривой | Та же фраза в текстовое поле (оператор печатает заранее заготовленное из шпаргалки) | «В зале шумно — то же самое текстом, логика та же» |
| Распознан не тот текст | Транскрипт неверный, ответ странный | «Отменить» → повторить фразу медленнее, ближе к гарнитуре. Вторая неудача → текст | «Видно, что услышал — поэтому мы показываем транскрипт до выполнения» |
| LLM медленный или недоступен | Ответ дольше 5 с или ошибка | Переключить `LLM_PROVIDER=rules` (горячая клавиша / команда в админке). Шаги 1, 2, 5, 6, 7 закрываются правилами | «Нейросеть недоступна — ассистент работает на правилах, это наш фолбэк» |
| Стенд или сеть площадки | Не грузится страница / /health красный | Второй ноутбук: локальный `docker compose up`, `http://localhost:8080` (микрофон на localhost работает), раздача интернета с телефона для LLM | «Переключаемся на локальную копию — всё работает и без облака» |
| Ничего не работает | — | Видео демо (3 мин, записано заранее на этих же репликах) | «Покажем запись того же сценария» |
| Неожиданный ответ ассистента | Ответ не совпал с таблицей | Не спорить с экраном. Если запись создана неверно — «Отменить» и идти дальше | «Отменили одной кнопкой — так это работает и у пользователя» |

**Если жюри хочет попробовать само** — это лучшая возможность, не отказываемся. Даём текстовое поле или микрофон, предлагаем «спросите про любую встречу или задачу». Покрытие перефразировок держим в голове: «у нас 100 эталонных фраз, включая ошибки распознавания».

## 5. Подготовка

### За сутки
- [ ] Стенд на HTTPS, `/health` зелёный по всем четырём зависимостям.
- [ ] `make demo-reset` — сбросить базу, заново импортировать CSV, выставить `FREEZE_NOW`. **Без сброса каждая репетиция оставляет дубли** («позвонить Ивану» × 5) и ломает шаги 3–5.
- [ ] `make demo-check` — прогнать реплики шагов 1–7 через `/api/chat` и сравнить с таблицей выше.
- [ ] Записать видео демо на этом сценарии.
- [ ] Свежий `make eval`, цифры на слайд 8.
- [ ] Подписка на `https://voice.planimetrika.online/calendar/demo.ics` в Яндекс Календаре на ноутбуке оператора; события видны.
- [ ] Проверить отмену обоими способами: кнопкой «Отменить» и фразой «отмени».
- [ ] Минимум 3 полных прогона с таймером. Цель — 2:45, запас 15 с.

### За час
- [ ] Гарнитура или петличка, а не встроенный микрофон ноутбука. Проверить в зале.
- [ ] Локальная копия на втором ноутбуке поднята и проверена.
- [ ] Шпаргалка с репликами открыта у оператора для копирования в текстовое поле.
- [ ] Отключены уведомления, заставка, автообновления; зарядка подключена.

### За 5 минут
- [ ] `make demo-reset`.
- [ ] Открыт экран диалога, звук ответа включён, панель «Сегодня / Неделя» видна.
- [ ] Видео демо открыто во вкладке на втором ноутбуке.

## 6. Что нужно от других чатов

| Чат | Что сделать для демо |
|---|---|
| 0 · Каркас | `make demo-reset`, `make demo-check`; переключение `LLM_PROVIDER` без перезапуска (или быстрая команда); второй стенд на localhost |
| 1 · NLU | шаги 1, 2, 5, 6, 7 закрываются правилами без LLM; «в три» в ответ на вопрос о времени |
| 2 · Диалог | тексты ответов как в таблице: абсолютная дата, перечисление конфликтов, «Последняя — … До этого — …», длинный список → количество + ближайшие; «встречу» ссылается на единственную встречу из последнего списка |
| 3 · Данные | поиск с фильтром «была» = прошлое; синоним ТЗ; при конфликте задача внутри интервала встречи тоже упоминается |
| 4 · Голос | задержка ответа ≤ 2,5 с на этих фразах; проверка на гарнитуре |
| 5 · Фронт | кнопки быстрых ответов при конфликте, «Отменить», крупный шрифт для проектора |

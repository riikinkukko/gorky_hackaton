## 0. Словарик

| Термин | Что значит простыми словами |
|---|---|
| **SPA** | Single Page Application: одна HTML-страница, всё остальное рисует JavaScript без перезагрузки |
| **PWA** | Progressive Web App: сайт, который можно «установить» на телефон иконкой и открывать без адресной строки, как приложение |
| **Service worker** | Скрипт, который браузер держит в фоне. У нас он кэширует статику (JS, CSS, иконки), чтобы приложение быстро открывалось |
| **Manifest** | Файл `manifest.webmanifest` с названием, иконками и цветами — по нему телефон делает «приложение» |
| **Прокси** | Посредник: dev-сервер Vite принимает запрос на `/api` и пересылает его бэкенду |
| **WebSocket (WS)** | Постоянное двустороннее соединение. По нему идёт звук на сервер и ответы обратно, без отдельных HTTP-запросов |
| **PCM / WAV** | PCM — «сырой» звук, просто числа-отсчёты. WAV — PCM с заголовком из 44 байт, где записаны частота и формат |
| **AudioWorklet** | Маленький обработчик звука, который браузер запускает в отдельном потоке. У нас он превращает звук микрофона в PCM 16 кГц |
| **Pre-roll / post-roll** | «Запас» звука до нажатия кнопки и после отпускания, чтобы не обрезать первое и последнее слово |
| **CSP** | Content-Security-Policy: заголовок, который говорит браузеру, откуда странице можно грузить скрипты, шрифты, звук и куда подключаться |
| **httpOnly-cookie** | Cookie, которую JavaScript страницы прочитать не может; браузер сам прикладывает её к запросам |
| **TTS / STT** | Text-to-Speech — озвучка текста; Speech-to-Text — распознавание речи |
| **speechSynthesis** | Встроенная в браузер озвучка текста (Web Speech API) |
| **Мок** | Поддельный бэкенд внутри браузера: интерфейс можно показывать и разрабатывать без сервера |

## 1. Стек, сборка и запуск

### 1.1. Из чего собран фронт (`frontend/package.json`)

Скрипты `npm run …`:

|---|---|

| `dev:mock` | Vite с мок-API: бэкенд не нужен, «сейчас» = 21.10.2026 14:00 МСК |
| `build` | Проверка типов + сборка в `dist/` (так собирает Docker и CI) |

| `seed` | Пересобрать `src/mock/seed.json` из CSV организаторов (`scripts/csv_to_seed.py`) |

Иконки PWA (192, 512, maskable 512, apple-touch 180) делает `python3 scripts/make_icons.py` из `public/icon.svg`.

### 1.2. `frontend/vite.config.ts` — три режима

- **Обычный** (`vite`). Прокси на `VITE_BACKEND_URL` (по умолчанию `http://localhost:8000`) для `/api`, `/health`, `/calendar` и `/ws` (у `/ws` включено `ws: true`, иначе WebSocket не проксируется).
- **`--mode mock`**. В код подставляются `VITE_USE_MOCK=1` и `VITE_FREEZE_NOW=2026-10-21T14:00:00+03:00`, `.env` для этого не нужен.
- **`--mode preview`**. Мок плюс `viteSingleFile`, PWA выключен.

**PWA (`VitePWA`):**
- `registerType: "autoUpdate"`: новая версия service worker ставится сама;
- manifest: имя «Помню — голосовой ассистент», короткое «Помню», `lang: "ru"`, `display: "standalone"` (без адресной строки), `theme_color: #E2553A` (наш оранжево-красный акцент), `background_color: #F4F1EA` («бумага»), четыре иконки, включая maskable для Android;
- `workbox.navigateFallbackDenylist` исключает `/api`, `/ws`, `/calendar`, `/health`: **API и голос service worker никогда не кэширует**, только статику. Иначе пользователь мог бы увидеть старое расписание.

### 1.3. Как запустить локально

| Вариант | Команды | Адрес |
|---|---|---|
| Только интерфейс, без бэкенда | `cd frontend && npm i && npm run dev:mock` | http://localhost:5173 |
| Интерфейс + бэкенд «вживую» | терминал 1: `make dev-api` (uvicorn на `:8000` с CSV организаторов); терминал 2: `make dev-web` (= `cd frontend && npm run dev`) | http://localhost:5173 |
| Весь стек в Docker, как на сервере | `make up` | http://localhost:8080 |

Микрофон на `localhost` браузеры разрешают и без HTTPS, поэтому локально голос работает.

### 1.4. Как собирается в Docker (`frontend/Dockerfile`, `frontend/nginx.conf`)

Сборка в две стадии:
1. `node:22-alpine`: `npm ci` → `npm run build`. Аргумент `VITE_USE_MOCK` по умолчанию `0` (настоящий API). Для стенда без бэкенда: `--build-arg VITE_USE_MOCK=1`.
2. `nginx:1.27-alpine` раздаёт `dist/` на порту 80. Это контейнер **`web`** в `docker-compose.yml`.

Что настроено в `nginx.conf`:
- `/assets/` — кэш на год (`immutable`): у файлов в имени хэш, новая версия получает новое имя;
- `sw.js`, `registerSW.js`, `workbox-*.js`, `manifest.webmanifest` — `no-cache`, **иначе обновление PWA «застрянет»** на старой версии;
- любой другой путь отдаёт `index.html` (SPA-фолбэк);
- gzip для CSS, JS, JSON, SVG, manifest.

### 1.5. Caddy перед `web` (`Caddyfile`)

Caddy — входная дверь стека. Он делит запросы:
- `/api/*`, `/ws/*`, `/calendar/*`, `/health`, `/docs`, `/openapi.json` → `api:8000` (бэкенд);
- всё остальное → `web:80` (наш nginx со статикой).

Поэтому фронт и бэкенд для браузера — **один адрес (same-origin)**: cookie прикладывается сама, CORS не нужен, WebSocket идёт на тот же хост.

На стенде https://voice.planimetrika.online сервер общий с другим приложением. Там работает режим «сосед» (`docker-compose.shared.yml`): Caddy слушает только `127.0.0.1:8080`, а HTTPS делает веб-сервер хоста (конфиги в `deploy/shared/`). Локально и на «чистом» VPS Caddy сам получает сертификат Let's Encrypt, если в `SITE_ADDRESS` указан домен.

**Заголовки безопасности (блок `header` в `Caddyfile`):**

| Заголовок | Что даёт |
|---|---|
| `Strict-Transport-Security` | Браузер год ходит на сайт только по HTTPS |
| `X-Content-Type-Options nosniff` | Браузер не «угадывает» тип файла |
| `Referrer-Policy strict-origin-when-cross-origin` | Не отдаёт полный адрес страницы чужим сайтам |
| `Permissions-Policy "microphone=(self)"` | Микрофон доступен только нашей странице, не встроенным чужим |
| `X-Frame-Options DENY` + `frame-ancestors 'none'` | Сайт нельзя встроить в чужой `<iframe>` (защита от кликджекинга) |
| `-Server` | Не сообщаем, какой веб-сервер стоит |

**CSP по частям:**
```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self';
img-src 'self' data:; media-src 'self' blob:; connect-src 'self' wss://{host};
worker-src 'self'; manifest-src 'self'; frame-ancestors 'none'; base-uri 'self';
form-action 'self'; object-src 'none'
```
- `script-src 'self'` — скрипты только наши. Поэтому AudioWorklet лежит **отдельным файлом** `src/audio/pcm-worklet.js` (Vite кладёт его в `assets/`), а не создаётся из `blob:`: такой worklet CSP бы не пропустила.
- `font-src 'self'` — **поэтому шрифты локальные.** Шрифт Onest (лицензия OFL, `public/fonts/OFL.txt`) лежит в `public/fonts/`, а подключается в `src/fonts.css`: кириллица и латиница, начертания 400–700, с `unicode-range`, поэтому браузер скачивает только нужные куски. С Google Fonts CSP пришлось бы ослаблять, а браузер при каждом открытии стучался бы на внешний сервер. Самый частый файл (кириллица 400) заранее подгружается через `<link rel="preload">` в `index.html`.
- `media-src 'self' blob:` — звук ответа проигрывается из `blob:`-адреса (`URL.createObjectURL`).
- `connect-src 'self' wss://{host}` — запросы и WebSocket только на свой хост.
- `worker-src 'self'`, `manifest-src 'self'` — service worker и manifest с нашего домена.

История: это пункт аудита безопасности SEC-09, фронт под него переделан в версии `web/v4` (коммит `c87069d`).

## 2. Структура `frontend/src`

```
src/
  main.tsx            точка входа: рендерит <App/> и подключает fonts.css + index.css
  App.tsx             экран входа или основной экран; раскладка
  config.ts           демо-пользователи и все тайминги
  index.css           токены цвета (светлая и тёмная тема), анимации, фокус, reduced-motion
  fonts.css           @font-face для Onest
  components/         то, что видно на экране
  hooks/              логика без разметки (диалог, микрофон, озвучка, связь с сервером)
  api/                всё общение с бэкендом и типы
  audio/              запись звука
  lib/                время в МСК, форматирование дат, проверка «обрезанного» транскрипта
  mock/               поддельный сервер для разработки и показа без бэкенда
```

### 2.1. `App.tsx` и `config.ts`

`App` при старте:
1. Выбирает бэкенд: `loadBackend()` из `api/index.ts` — настоящий (`http.ts`) или мок (`mock/backend.ts`, грузится отдельным чанком и в боевую сборку не попадает).
2. Спрашивает `GET /api/session`. Пока ответа нет, ничего не рисует (`auth === undefined`). 401 — показывает `Login`, есть сессия — `Main`.
3. Передаёт бэкенду обработчик `onUnauthorized`: любой 401 → выключить микрофон, показать вход с плашкой «Сессия закончилась — войдите снова.»

`Main` — основной экран: `Header` сверху; слева колонка `Banners` → `ChatHistory` → `Composer`; справа `AgendaPanel` шириной 340 px. На экранах уже `lg` (1024 px) панели справа нет: она открывается снизу «шторкой» на 75 % высоты по кнопке «Сегодня» в шапке. `DevPanel` рисуется только в мок-режиме.

`config.ts`:
- `DEMO_USERS`: 1 «Демо» (1000 записей организаторов, 2024–2027), 2 «Анна» и 3 «Пётр» (чистый календарь). Список совпадает с seed бэкенда; в контракте он не описан.
- `SLOW_AFTER_MS = 3000` — через сколько показать «Думаю дольше обычного…»;
- `TIMEOUT_MS = 20000` — когда сдаться и показать ошибку;
- `AUDIO_WAIT_MS = 6000` — сколько ждать звук ответа с сервера, прежде чем озвучить браузером;
- `MAX_RECORD_MS = 30000` — автостоп записи.

### 2.3. `hooks/` — логика

- **`useAssistant.ts`** — сердце интерфейса. Хранит ленту сообщений `Msg` (реплика пользователя или ответ ассистента со статусом `pending | done | error`). Умеет `sendText`, `retry`, `undo` и голос (`startVoice`, `stopVoice`, `cancelVoice`). Ставит таймеры «долго» и «сдаюсь». Решает, у какого ответа показывать «Отменить». Увеличивает `agendaVersion`, когда данные изменились (панель перечитывается). Держит `highlight` — какие записи подсветить в панели.
- **`useRecorder.ts`** — React-обёртка над `micEngine`. Состояния микрофона `MicState`: `idle`, `starting`, `recording`, `denied`, `insecure` (страница не по HTTPS), `unsupported`, `error`. Следит за разрешением на микрофон через Permissions API. Гасит микрофон, когда вкладку свернули, и снова «прогревает», когда вернулись.
- **`useSpeaker.ts`** — озвучка. `playBlob` проигрывает звук с сервера, `speakText` говорит через `speechSynthesis` (`ru-RU`, локальный русский голос в приоритете, скорость 1,05). Выключатель запоминается в `localStorage["pomnyu.voice"]`. Если браузер запретил автоплей, молчит: текст и так на экране.
- **`useHealth.ts`** — опрашивает `/health` раз в 30 с, а когда сервер лежит — раз в 5 с, плюс на событие `online`. Красит точку в шапке и сам снимает баннер «Сервер недоступен». При первом ответе берёт `now` сервера: если на стенде стоит `FREEZE_NOW`, «сегодня» в панели совпадёт с «сегодня» ассистента.

### 2.4. `api/` — общение с бэкендом

- **`types.ts`** — типы фронта, зеркало `backend/app/contracts.py`: `Item`, `ReplyAction` (`created | listed | found | updated | completed | deleted | undone | clarify | conflict | none`), `AssistantReply` (`text`, `action`, `items`, `suggestions`, `debug`), `Health`, сообщения `/ws/voice`. Здесь же два множества: `MUTATING` (после этих действий данные изменились: панель перечитать) и `UNDOABLE` (`created`, `updated`, `completed`, `deleted`: можно отменить).
- **`backend.ts`** — интерфейс `Backend`: всё, что фронт знает о сервере (`session`, `login`, `logout`, `chat`, `undo`, `items`, `tts`, `health`, `openVoice`). Плюс класс ошибки `BackendError` с видами `network`, `http`, `timeout`, `aborted`, `protocol`, `unauthorized` (401), `forbidden` (403), `rate` (429, с `retryAfterS`).
- **`http.ts`** — настоящая реализация. `fetch` с `credentials: "same-origin"`. Ошибки переводятся в `BackendError`: 401 → `onUnauthorized()`, 429 → читаем `Retry-After` (по умолчанию 2 с), 403 → «Доступ запрещён». WebSocket для голоса: пока сокет открывается, сообщения копятся в очереди; бинарному кадру с аудио ответа проставляется MIME из `audio_mime`; закрытие с кодом 4401 или 1008 без ответа → экран входа.
- **`index.ts`** — выбор `http` или мока по `VITE_USE_MOCK`.
- **`contracts.ts`** — копия контракта бэкенда на TypeScript. Её ведёт владелец контракта (чат 0), фронт её не правит.
- **`contracts.check.ts`** — проверка совместимости **на уровне типов**, без запуска кода. Утверждения вида `Assert<Same<F.ItemType, C.ItemType>>`: типы записи, статусы и `action` должны совпадать точно, а `Item` и `AssistantReply` контракта — подходить под типы фронта. Запуск: `npm run check:contract` (= `tsc -p tsconfig.contract.json`). Если бэкенд добавит новый `action`, а фронт о нём не узнает, команда упадёт с ошибкой компиляции. В обычную сборку проверка не входит, чтобы фронт собирался и без `contracts.ts`.

### 2.5. `audio/` — как пишется звук

**Проблема, из-за которой всё так устроено.** Сначала запись шла через `MediaRecorder`: на каждое нажатие заново открывался микрофон. Он стартует через 100–500 мс после нажатия, и первый слог терялся: на живом тесте 22.10 «Удали» распознавалось как «Дали», «Перенеси» — как «Неси». Для голосового ассистента это опасно: обрезанная команда может сделать не то.

**Решение (`web/v3`, коммит `b770e93`), файл `micEngine.ts`:**
1. **Микрофон наготове.** Если разрешение уже дано, поток с микрофона открыт, пока вкладка активна (не на iOS, см. ниже). Рядом с кнопкой — зелёная точка «наготове» с подсказкой: на сервер уходит только то, что сказано с нажатой кнопкой, плюс 0,4 с до и после.
2. **Кольцевой буфер (pre-roll).** Последние `PREROLL_MS = 400` мс звука постоянно лежат в памяти. При нажатии они уходят на сервер первыми, поэтому начало слова сохраняется, даже если человек заговорил одновременно с нажатием.
3. **Дозапись (post-roll).** После отпускания пишется ещё `POSTROLL_MS = 400` мс: последний слог не срезается, если кнопку отпустили на нём.
4. **Потоковая отправка.** Кадры по 20 мс склеиваются в куски по ~100 мс и уходят по ходу речи. На этом держится промежуточный транскрипт.
5. **Гигиена.** Микрофон наготове гаснет при сворачивании вкладки и через 5 минут без записи: индикатор записи не должен гореть часами.

**`pcm-worklet.js` + `pcmWorklet.ts`.** Worklet получает звук с частотой микрофона (обычно 44,1 или 48 кГц), усредняет отсчёты до 16 кГц (простой фильтр, для распознавания достаточно) и отдаёт кадры по 320 отсчётов (20 мс) в формате PCM 16 бит. `streamingWavHeader()` делает 44-байтный заголовок WAV с размером «до конца потока» (`0xFFFFFFFF`), потому что длина записи заранее неизвестна. Для старых браузеров без AudioWorklet есть запасной путь `ScriptProcessor`.

Итог: **во всех браузерах на сервер идёт один формат — `audio/wav`, PCM 16 кГц моно**. Это ~32 КБ/с, 30 с записи ≈ 1 МБ (лимит сервера 2 МБ).

**iOS Safari — особый режим** (`keepWarm = false` на iOS):
- поток постоянно не держим: на iPhone горит оранжевый индикатор, а в фоне поток рвётся;
- микрофон открывается по нажатию (`pointerdown`), а надпись «Говорите…» появляется **только когда пошли реальные кадры** (≈0,3 с). Пока их нет, на кнопке крутится индикатор «Включаю микрофон…»;
- после записи поток живёт ещё 15 с (`IOS_LINGER_MS`): короткий ответ на уточнение («в три», «да») тоже получает pre-roll;
- AudioContext на iOS запускается только по жесту пользователя, поэтому граф собирается на **первом любом нажатии на странице**, даже на выборе пользователя на экране входа (`micEngine.prepare()`).

**Режимы кнопки (`Composer.tsx`):**
- **«Удерживать»** (по умолчанию) — классический push-to-talk: зажал, говоришь, отпустил — отправилось. `setPointerCapture`: если палец съехал с кнопки, запись не обрывается. Отключены контекстное меню и «лупа» iOS при долгом нажатии (`onContextMenu`, `WebkitTouchCallout: none`, `touch-none`, `select-none`).
- **«Нажать»** — нажал один раз, говоришь, нажал ещё раз — отправилось. Удобно для длинных фраз и для людей, которым трудно держать палец.
- Выбор запоминается в `localStorage["pomnyu.micmode"]`.
- С клавиатуры: **пробел** работает как кнопка (в обоих режимах), **Esc** отменяет запись. Сама кнопка реагирует и на Enter.
- Защита от случайностей: нажатие короче 400 мс не отправляется, а показывает подсказку «Удерживайте кнопку, пока говорите, — или переключитесь в режим «Нажать»». Отпустили раньше, чем микрофон заработал (первый запрос разрешения), — подсказка «Микрофон готов. Теперь зажмите кнопку и говорите.» Через 30 с запись останавливается сама.
- Нажатие на кнопку **перебивает озвучку** ответа (`speaker.stop()`).

Отладка на телефоне: `localStorage.setItem("pomnyu.micdebug","1")`, в консоли появятся строки `[mic]` с таймингами старта.

### 2.6. `lib/`

- **`time.ts`** — всё время считается в **Europe/Moscow**, независимо от часового пояса телефона (в МСК нет перехода на летнее время, хватает смещения +03:00). `now()` берёт `VITE_FREEZE_NOW` (мок), иначе часы сервера из `/health`, иначе часы браузера.
- **`format.ts`** — `formatWhen()` выдаёт абсолютную дату «чт, 22 октября, 10:00» (год дописывается, только если он не текущий); встреча с концом — «10:00–11:00». Также `dayHeading()` («Сегодня», «Завтра», «Пятница, 23 октября»), подписи типов и статусов, `plural()` для «запись / записи / записей».
- **`transcript.ts`** — `looksClipped()`: если голосовая реплика начинается с «огрызка» короче трёх букв и это не настоящее короткое слово («в», «на», «а», «да»…), под пузырём появляется предупреждение: «Похоже, начало фразы не расслышано. Если ассистент понял не так — скажите ещё раз или нажмите «Отменить».»

### 2.7. `mock/`

`server.ts` — мок-сервер по контракту. Seed — 1000 записей из CSV организаторов (id совпадают с `golden_eval`), правила понимания фраз, диалог, отмена. `backend.ts` — реализация интерфейса `Backend` поверх него: имитирует задержку 350–650 мс, «сервер недоступен», «долгий ответ», 429. Голос в моке: транскрипт берётся из распознавания речи браузера (Chrome/Edge), а где его нет — по очереди подставляются фразы демо-сценария. `settings.ts` — переключатели для `DevPanel`. Мок — не замена настоящему NLU: он нужен для вёрстки и показа без сервера.

## 3. Поток пользователя по шагам

### Шаг 1. Вход демо-пользователя
1. `App.tsx` → `backend.session()` → `GET /api/session`. Есть cookie — сразу основной экран, иначе `Login`.
2. Нажатие на пользователя → `backend.login(id)` → **`POST /api/session {"user_id": 1}`** (`backend/app/api/session.py`). Сервер проверяет, что пользователь есть среди демо (иначе 403 «Неизвестный демо-пользователь»), подписывает токен HMAC-SHA256 и ставит cookie `pomnyu_session`: `httpOnly`, `secure`, `samesite=strict`, срок 24 часа (`session_ttl_s = 86400`). В ответе — `{"user_id", "session_id"}`. Вход ограничен: 10 попыток в минуту с одного IP.
3. Фронт хранит только `session_id`: он нужен для `/api/chat`, `/api/undo` и `/ws/voice`, по нему сервер помнит контекст диалога. Сам токен JavaScript не видит.
4. «Сменить пользователя» (аватар в шапке) → `DELETE /api/session` + выключение микрофона.

### Шаг 2. Текстовая реплика
1. Пользователь пишет в поле или нажимает пример / быструю кнопку → `useAssistant.sendText()`.
2. В ленту сразу добавляются пузырь пользователя и пузырь ассистента в статусе `pending` (три прыгающие точки). Озвучка прошлого ответа останавливается.
3. **`POST /api/chat {"text", "session_id"}`** (`backend/app/api/chat.py`). Сервер: лимит 20 реплик в минуту на сессию → `run_turn()` → ответ `AssistantReply`.
4. Через 3 с без ответа — «Думаю дольше обычного…». Через 20 с запрос отменяется и показывается ошибка «Сервер слишком долго не отвечает.» с кнопкой «Повторить».
5. Ответ пришёл → `finish()`: текст, карточки, кнопки. Если данные изменились — панель перечитывается, новые записи подсвечиваются.
6. Озвучка: `POST /api/tts`. Пришло пустое тело (`TTS_PROVIDER=browser|none`) — фронт запоминает, что серверной озвучки нет, больше её не спрашивает и говорит через `speechSynthesis`.

### Шаг 3. Голосовая реплика (`/ws/voice`)
1. Нажатие на кнопку → `startVoice()` → `backend.openVoice()` открывает `wss://<хост>/ws/voice?session_id=…`. Пользователь определяется по cookie: браузер прикладывает её к same-origin WebSocket сам.
2. Сразу уходит `{"type":"start","mime":"audio/wav"}`, затем первый бинарный кадр: заголовок WAV + pre-roll. Если сокет ещё открывается, всё ждёт в очереди.
3. Когда пошли реальные кадры, появляется пунктирный пузырь «Слушаю…», куски PCM по ~100 мс уходят по ходу речи.
4. Сервер шлёт **`{"type":"transcript","text","final"}`**. Промежуточный текст печатается в пунктирном пузыре с курсором: ошибку распознавания видно ещё до ответа.
5. Отпустили кнопку → пузырь пользователя появляется сразу (с промежуточным текстом или «…»), рядом — `pending`. Пишется ещё 400 мс post-roll, затем **`{"type":"end"}`**. Финальный транскрипт заменяет текст в пузыре.
6. Сервер шлёт **`{"type":"reply", …AssistantReply, "audio_mime"}`**. Текст и карточки показываются сразу.
7. Озвучка:
   - `audio_mime = null` (при `TTS_PROVIDER=browser` сервер не синтезирует, его `NullTTS` объявляет пустой MIME) → **сразу `speechSynthesis` браузера**, сокет закрывается;
   - `audio_mime` есть → ждём бинарный кадр со звуком. Пришёл — играем; не пришёл за 6 с или пришёл пустым — говорит браузер.
8. Ошибка `{"type":"error","message"}`, например «Не расслышал, повторите, пожалуйста.» или «Сервер занят, повторите через пару секунд.» (`backend/app/voice/limits.py`). Пока пузыря ответа нет, сообщение показывается подсказкой над кнопкой. Если пузырь уже есть, он становится ошибкой. Сервер вслед за `error` присылает `reply` с тем же текстом, чтобы его было слышно, поэтому в итоге в ленте обычно оказывается обычный ответ с этим текстом, и он озвучивается.

### Шаг 4. Карточки записей
- Под ответом показываются до 5 карточек `ItemCard`, остальные — по кнопке «Показать ещё N».
- Пометка зависит от `action` (таблица `MARK` в `ChatHistory.tsx`): `created` → **«Новая»**, `updated` → **«Изменена»**, `completed` → «Отмечена», `deleted` → «Удалена» (карточка бледная и зачёркнутая), `undone` → «Как было». Пометка с заливкой акцентом, рамка карточки вспыхивает (анимация `flash`, 2,4 с).
- При `action = "conflict"` над карточками стоит надпись **«Пересекается с»**: карточки показывают, с чем столкнулась новая встреча, а варианты («16:30», «Всё равно 15:30», «Отмена») приходят быстрыми кнопками.
- `suggestions` из ответа — кнопки быстрых ответов, **только под последним ответом**. Кнопку «Отменить» из `suggestions` фронт скрывает: для этого есть своя кнопка.

### Шаг 5. Кнопка «Отменить»
1. Появляется у ответа с действием из `UNDOABLE` и **только у последнего такого действия**: новое действие гасит кнопку у предыдущего.
2. Нажатие → кнопка гаснет, появляется `pending` → **`POST /api/undo {"session_id"}`**. На сервере это то же самое, что сказать «отмени»: незавершённое уточнение сбрасывается и выполняется ход с текстом «отмени». Журнал действий один, поэтому отмена кнопкой, текстом и голосом работает одинаково.
3. Ответ `action = "undone"`. У отменённого ответа появляется «Действие отменено». Если отменили **создание**, карточка исчезает из истории и из панели. Если отменили изменение, приходит запись с пометкой «Как было».
4. Ошибка → кнопка «Отменить» возвращается.

### Шаг 6. Панель «Сегодня / Неделя»
- `AgendaPanel` запрашивает `GET /api/items?from=…&to=…` за день или за неделю (с понедельника), время в МСК с `+03:00`.
- Перечитывается после каждого изменения данных (`agendaVersion`), после синхронизации часов с сервером и при смене вкладки.
- Только что созданные, изменённые и отмеченные записи подсвечиваются. После отмены подсветки нет: запись могла исчезнуть.
- На мобильном счётчик «Сегодня N» виден на кнопке в шапке, панель открывается шторкой снизу.

### Шаг 7. Выключатель звука
Кнопка «Озвучка / Без звука» в шапке. Выключение сразу обрывает текущую озвучку. Состояние сохраняется между визитами. Текст ответа виден всегда, звук — дополнение.

### Шаг 8. Ошибки
| Что случилось | Что видит пользователь | Где в коде |
|---|---|---|
| **401** на любом запросе или WS закрыт с 4401/1008 | Экран входа: «Сессия закончилась — войдите снова.» | `http.ts` → `onUnauthorized` → `App.tsx` |
| **429** (слишком часто) | Пузырь-ошибка «Слишком часто — подождите пару секунд» и кнопка «Повторить через N с»: оживает по `Retry-After`. Автоповторов нет | `http.ts` (`RATE_LIMIT_MESSAGE`), `RetryButton` в `ChatHistory.tsx` |
| 429 на `/api/tts` | Ничего: молча говорит браузер | `http.ts` → `tts()` |
| **«Сервер занят»** (очередь к распознаванию переполнена) | Текст «Сервер занят, повторите через пару секунд.» в ленте или подсказкой над кнопкой | `/ws/voice` → `onError` / `onReply` в `useAssistant.ts` |
| Сеть / сервер лежит | Красный баннер «Сервер недоступен», красная точка, автопроверка каждые 5 с; в пузыре — «Не удаётся связаться с сервером.» | `useHealth.ts`, `Banners.tsx` |
| Долгий ответ | «Думаю дольше обычного…» (3 с) → ошибка + «Повторить» (20 с) | `useAssistant.ts` → `track()` |
| Нет HTTPS / микрофон запрещён / не найден | Жёлтый баннер с инструкцией; голос выключен, текст работает | `useRecorder.ts`, `Banners.tsx` |

Для текстовых реплик у ошибки есть «Повторить». Голосовую реплику повторить кнопкой нельзя: нужно сказать ещё раз.

## 4. UX-решения и почему

1. **Абсолютные даты в ответах и карточках.** «чт, 22 октября, 10:00», а не «завтра». Если ассистент понял «в пятницу» не так, человек увидит и услышит это сразу. Тексты ответов формирует бэкенд, карточки — `formatWhen()` на фронте, в одном стиле. Время всегда в МСК, поэтому телефон в другом поясе не сдвинет даты.
2. **Карточки рядом с ответом, а не только в календаре.** Результат действия виден там же, где команда: что создано, на когда, какого типа. Пометка «Новая / Изменена» снимает вопрос «а он точно сделал?». Панель справа показывает то же в контексте дня.
3. **Отмена вместо подтверждения на каждое действие.** Спрашивать «Точно создать?» на каждую команду — вдвое больше шагов голосом. Действие выполняется сразу, а ошибка исправляется одной кнопкой или словом «отмени». Исключение — удаление: его ассистент сначала уточняет («Удалить задачу «Купить хлеб»?»), а удаление на сервере мягкое. Кнопка «Отменить» есть только у последнего действия, чтобы не было путаницы, что именно отменится.
4. **Подсказки вместо инструкции.** Пустой экран — «Скажите, что запомнить» и пять кликабельных примеров (они же — фразы демо). Плейсхолдер поля: «Или напишите: «Что у меня на неделе?»». Подпись под кнопкой меняется по состоянию: «Зажмите и говорите» → «Говорите · отпустите, чтобы отправить» → «Включаю микрофон…». Пустая панель подсказывает: «Скажите: «Напомни завтра в 10 позвонить Ивану»».
5. **Транскрипт до ответа.** Пользователь видит, что услышал ассистент, ещё во время речи. Распознавание ошиблось — видно сразу, а не по странному результату.
6. **Когда данных не хватает — уточняющий вопрос.** Ассистент не выдумывает время. «Поставь встречу с Иваном завтра» → «На какое время поставить встречу?» и быстрые кнопки «10:00 / 15:00 / 18:00». Ответить можно кнопкой, голосом («в три») или текстом. Интерфейс делает такой ответ лёгким: кнопки под последним сообщением, на iPhone микрофон ещё 15 с остаётся открытым — короткий ответ не обрежется. При конфликте — то же: что пересекается (карточки «Пересекается с») и варианты решения кнопками. **По словам ТЗ, это поведение отдельно оценивается в критерии UX**, поэтому оно стоит в демо-сценарии (шаги 3 и 4 в `docs/pitch/DEMO.md`).
7. **Текст всегда доступен.** Поле ввода не прячется, даже когда голос работает. Нет микрофона или в зале шумно — пользователь не застревает.
8. **Честные состояния.** Каждое «почему не работает» имеет свой баннер с действием («Я разрешил», «Проверить сейчас»), а не общую ошибку.
9. **Тёмная тема.** Включается автоматически по настройке системы (`prefers-color-scheme: dark` в `index.css`): весь набор цветовых токенов переопределён, включая цвета типов записей. Ручного переключателя в интерфейсе нет, хотя CSS к нему готов (атрибут `data-theme`).
10. **Спокойный визуальный язык.** Тёплая «бумага» (`#f4f1ea`) и один сигнальный цвет (`#e2553a`) — для голоса и изменений. Тип записи — цветная точка, а не заливка карточки: в длинном списке глаз цепляется за пометки изменений, а не за раскраску.
11. **Мобильный вид — основной.** `viewport-fit=cover` и отступ под «чёлку» и полосу жестов (`safe-area-inset-bottom`), большая кнопка у большого пальца внизу, панель шторкой снизу, подписи кнопок в шапке на узком экране скрываются до иконок. PWA ставится на главный экран.
12. **Озвучку можно перебить.** Новое нажатие на кнопку обрывает голос ассистента: не нужно ждать, пока он договорит.

## 5. Что ТЗ требует от интерфейса и что сделано сверх

**Минимум ТЗ:** «достаточно страницы с кнопкой начала записи, историей диалога и ответом ассистента».

| Требование | Где |
|---|---|
| Кнопка начала записи | `Composer.tsx` → `MicButton` |
| История диалога | `ChatHistory.tsx` |
| Ответ ассистента | Пузырь ассистента + озвучка (`useSpeaker.ts`) |

**Сверх минимума:**
- два режима кнопки («Удерживать» / «Нажать»), пробел и Esc с клавиатуры, автостоп 30 с, защита от случайного тапа;
- pre-roll / post-roll и микрофон наготове — начало и конец фразы не теряются;
- промежуточный транскрипт и предупреждение об обрезанном начале;
- карточки записей с пометками «Новая / Изменена / Отмечена / Удалена / Как было» и «Пересекается с»;
- кнопка «Отменить» (`/api/undo`);
- быстрые ответы из `suggestions` (уточнения, конфликты);
- панель «Сегодня / Неделя» с подсветкой изменений и часами сервера;
- текстовый ввод всегда;
- выключатель звука, фолбэк озвучки на браузер;
- баннеры для HTTPS, разрешения, отсутствия микрофона, падения сервера; обработка 401 / 429 / таймаутов;
- демо-вход с httpOnly-cookie, CSP без внешних доменов;
- PWA (установка на телефон), тёмная тема, адаптивная вёрстка;
- мок-режим и `DevPanel` для показа без сервера; сборка «один HTML-файл».

## 6. Доступность и браузеры

### 6.1. Доступность (что есть)
- Лента — `role="log"` с `aria-live="polite"`: экранный диктор зачитывает новые реплики. Подпись под кнопкой тоже `aria-live`.
- Баннеры: `role="alert"` (сервер) и `role="status"` (микрофон); плашка на входе — `role="alert"`.
- Кнопка микрофона: `aria-label` «Начать запись / Остановить запись», `aria-pressed`. Режимы — `role="radiogroup"` / `role="radio"`. Шторка панели — `role="dialog" aria-modal`.
- Видимый фокус (`:focus-visible`, обводка акцентом), управление с клавиатуры (пробел, Enter, Esc).
- `prefers-reduced-motion`: анимации практически выключаются.
- Крупная кнопка (80 px) — легко попасть пальцем.

### 6.2. HTTPS обязателен
Браузер даёт микрофон только в «безопасном контексте»: `https://` или `localhost`. `useRecorder.initialMicState()` проверяет `window.isSecureContext` и при `http://` по IP показывает баннер «Микрофон работает только по HTTPS». Поэтому стенд на HTTPS. Cookie сессии тоже ставится с флагом `secure`.

### 6.3. Safari и iPhone
- **Формат записи.** Раньше это было больное место: `MediaRecorder` в Safari пишет `audio/mp4`, в Chrome — webm. Бэкенд до сих пор умеет принимать `audio/mp4` (`backend/app/voice/audio.py`), и в `docs/CONTRACT.md` это упомянуто. **Но с `web/v3` фронт MediaRecorder не использует**: через AudioWorklet он сам делает WAV PCM 16 кГц, и во всех браузерах, включая Safari, шлёт `"mime":"audio/wav"`. Разницы форматов между браузерами больше нет.
- **AudioContext** на iOS стартует только по жесту — собираем его на первом нажатии на странице.
- **Микрофон не держим постоянно** — открываем по нажатию, ждём реальные кадры, держим 15 с после записи (см. 2.5).
- **Автоплей звука** может быть запрещён — тогда молча, текст на экране.
- `webkitAudioContext` поддержан для старых Safari.

### 6.4. Что проверить перед защитой (чек-лист)
- [ ] Стенд открывается по `https://`, замок в адресной строке, точка в шапке зелёная.
- [ ] iPhone (Safari) и Android (Chrome): вход, разрешение микрофона, 10 раз «Удали эту задачу» — фраза начинается с «Удали» (процедура — `qa/DEVICE_CHECK.md`, раздел «Проверка на телефоне» в `frontend/README.md`).
- [ ] iPhone: первая фраза после паузы > 15 с — дождаться «Говорите…», только потом говорить.
- [ ] Озвучка слышна на iPhone и Android (на iOS проверить, что `speechSynthesis` говорит после ответа, а не молчит).
- [ ] Тёмная тема телефона — всё читается.
- [ ] Узкий экран (iPhone SE, 375 px): шапка не переносится, кнопка и поле ввода помещаются, шторка открывается и закрывается.
- [ ] PWA: «На экран «Домой»» → открывается без адресной строки, иконка правильная.

## 8. Слабые места и что улучшить

Честно, с приоритетом. На защите лучше назвать самим, чем ждать вопроса.

1. **Результатов слепого теста ещё нет.** Тест назначен на 26–27.10 (протокол — `qa/blind/`, итоги — в `qa/REPORT.md`). До этого UX проверен живыми прогонами команды и проверкой на телефонах, но не на людях со стороны. → После теста внести цифры в ответы жюри.
2. **iPhone после паузы.** Если сказать фразу сразу после нажатия, когда микрофон закрыт (> 15 с простоя), начало может обрезаться: pre-roll взять неоткуда. Есть «Говорите…» и предупреждение под пузырём, но это смягчение, а не решение. → Держать поток дольше или явнее показывать «подождите».
3. **Нет «Повторить» для голосовых ошибок** — только сказать ещё раз. → Сохранять запись и давать переотправить.
4. **Нет ручного переключателя темы** (CSS готов, кнопки нет).
5. **`npm run check:contract` не в CI.** CI (`.github/workflows/ci.yml`) делает только `npm ci` и `npm run build`. Расхождение с контрактом поймается, только если кто-то запустит проверку руками. → Добавить шаг в CI. Кроме того, проверка не сравнивает сообщения `/ws/voice` (например, у `audio_mime` разные типы в `contracts.ts` и `types.ts`).
6. **Нет автотестов фронта** (ни юнит, ни e2e в браузере). Поведение защищают проверки QA (`qa/regress.py --web` следит за константами pre/post-roll) и ручные чек-листы.
7. **Отмена — только последнего действия.** Истории действий с выбором, что отменить, нет.
8. **Список демо-пользователей зашит** в `config.ts` и должен совпадать с бэкендом вручную.
9. **`style-src 'unsafe-inline'` в CSP** — самое мягкое место политики. → Проверить, можно ли убрать.
10. **Нет офлайн-режима для команд.** Service worker кэширует только статику: без сети приложение откроется, но команды не выполнятся (так задумано, показывается баннер).
11. **Доступность не проверялась инструментами** (Lighthouse, VoiceOver/TalkBack). Мелкий «бледный» текст (`text-faint`) может не дотягивать по контрасту.
12. **Озвучка браузером на iOS** может не сработать, если Safari посчитает её не вызванной жестом: ответ приходит асинхронно. Проверить на устройстве.

## 9. Вопросы жюри с ответами

**1. Почему веб / PWA?**
Открывается по ссылке на любом устройстве, жюри может попробовать с телефона прямо сейчас. PWA ставится на главный экран иконкой и открывается без адресной строки, как приложение. Один код для iPhone, Android и ноутбука, обновление — просто деплой, без магазинов.

**2. Почему не нативное приложение?**
За время хакатона нативное приложение означало бы две кодовые базы и проверку в магазинах, а ТЗ просит прототип и прямо говорит, что страницы достаточно. Всё, что нам нужно от устройства — микрофон, звук, иконка на экране, — веб даёт. Если продукт пойдёт дальше, нативная оболочка понадобится для фоновых push-напоминаний и голосовой активации; API для неё уже есть.

**3. Как сделан push-to-talk?**
Кнопка ловит `pointerdown` / `pointerup` с захватом указателя: палец может съехать с кнопки, запись не оборвётся. Короткое нажатие (< 400 мс) не отправляется, а подсказывает. Есть второй режим «Нажать» — для длинных фраз. Пробел работает как кнопка, Esc отменяет, через 30 с автостоп. Новое нажатие перебивает озвучку.

**4. Почему не обрезаются первые слова?**
На живом тесте «Удали» превращалось в «Дали»: MediaRecorder стартует с задержкой до полсекунды. Мы заменили его на AudioWorklet: микрофон наготове, последние 400 мс лежат в кольцевом буфере и уходят вместе с записью, после отпускания пишем ещё 400 мс. На сервер идёт только то, что сказано с нажатой кнопкой, плюс эти 0,4 с с каждой стороны. Микрофон гаснет при сворачивании вкладки и через 5 минут простоя.

**5. Что видит пользователь, пока ассистент думает?**
Во время речи — промежуточный транскрипт в пунктирном пузыре. После отпускания пузырь с фразой появляется сразу, рядом — три прыгающие точки. Через 3 с — «Думаю дольше обычного…», через 20 с — понятная ошибка и «Повторить». Текст ответа приходит раньше звука и показывается сразу.

**6. Как сделана отмена? Почему не подтверждения?**
Подтверждение на каждое действие удваивает голосовой диалог. Мы выполняем сразу, показываем результат с абсолютной датой и даём «Отменить» — кнопкой или словом «отмени». Обе дороги ведут в один журнал действий на сервере (`POST /api/undo` = ход «отмени»). Отмена создания убирает карточку, отмена изменения показывает «Как было». Удаление — исключение: его ассистент сначала переспрашивает.

**7. Что если ассистенту не хватает данных?**
Он задаёт уточняющий вопрос и не выдумывает: «На какое время поставить встречу?» с кнопками 10:00 / 15:00 / 18:00. Ответить можно кнопкой, голосом («в три») или текстом — контекст диалога сервер держит по `session_id`. При конфликте показываем, с чем пересекается, и предлагаем свободное время кнопкой.

**8. Как вы проверяли UX?**
Три уровня. Живые тесты 22 и 23.10 на стенде: команда пользовалась ассистентом своими словами, реплики из лога (49 штук + 8 со скриншотов) разобраны в `qa/REPORT.md` и превращены в регрессионные тесты. Обрезанное начало фразы нашли именно так и исправили в `web/v3`. Проверка на телефонах по чек-листу `qa/DEVICE_CHECK.md`: 10 повторов «Удали эту задачу» на iPhone и Android. Слепой тест 26–27.10: люди, не видевшие проект, получают карточки-ситуации без названий команд и говорят своими словами, ведущий молчит (протокол `qa/blind/`). *[Сюда — итоги слепого теста после 27.10.]*

**9. А если микрофона нет или в зале шумно?**
Поле для текста есть всегда, логика та же. Для каждой проблемы с микрофоном — свой баннер с инструкцией: нет HTTPS, доступ запрещён, микрофон не найден, браузер не умеет.

**10. Как фронт и бэкенд договариваются о формате?**
Есть контракт (`backend/app/contracts.py`), его копия на TypeScript — `frontend/src/api/contracts.ts`. `npm run check:contract` на уровне типов проверяет, что фронт понимает все виды действий и все поля записей. Весь доступ к серверу — через один интерфейс `Backend`, поэтому для разработки его можно подменить моком.

**11. Как с безопасностью во фронте?**
Вход — подписанная httpOnly-cookie: JavaScript её не видит, украсть её через XSS нельзя. CSP разрешает скрипты, шрифты и подключения только с нашего домена. Поэтому шрифт лежит у нас, а AudioWorklet — отдельный файл. Сайт нельзя встроить в чужой iframe, микрофон разрешён только нашей странице. Service worker не кэширует API.

**12. Работает ли на iPhone? Почему даты в МСК?**
Да. Для Safari отдельный режим микрофона: открываем по нажатию, «Говорите…» — только когда звук реально пошёл, 15 с после записи держим открытым для ответа на уточнение. Формат один для всех браузеров — WAV. Время везде в Europe/Moscow и синхронизируется с часами сервера, поэтому телефон в другом поясе не сдвинет «сегодня».

## Шпаргалка на один экран

- **Стек:** React 19 + Vite + TypeScript + Tailwind 4 + PWA. Docker: node:22 собирает → nginx в контейнере `web` раздаёт → Caddy впереди (`/api`, `/ws` → бэкенд, остальное → `web`).
- **Запуск:** `npm run dev:mock` (без бэкенда) · `make dev-api` + `make dev-web` (прокси `/api`, `/ws` на `:8000`) · `make up` → `localhost:8080`.
- **Главные файлы:** `App.tsx` · `hooks/useAssistant.ts` (диалог) · `audio/micEngine.ts` (запись) · `api/http.ts` (сервер) · `components/Composer.tsx` (кнопка) · `ChatHistory.tsx` + `ItemCard.tsx` (лента и карточки) · `AgendaPanel.tsx` (панель).
- **Эндпоинты:** `POST/GET/DELETE /api/session` (cookie `pomnyu_session`, сутки) · `POST /api/chat` · `POST /api/undo` · `GET /api/items` · `POST /api/tts` · `GET /health` · `WS /ws/voice`: `start` → WAV-кадры → `end` ← `transcript` ← `reply` (+ звук или `audio_mime=null` → `speechSynthesis`).
- **Запись:** AudioWorklet → PCM 16 кГц → WAV во всех браузерах. Pre-roll 400 мс + post-roll 400 мс, куски по 100 мс. iOS: микрофон по нажатию, держим 15 с. Режимы «Удерживать» / «Нажать», пробел, Esc, автостоп 30 с, тап < 400 мс — подсказка.
- **UX-принципы:** абсолютные даты · карточки рядом с ответом (Новая / Изменена / Пересекается с) · отмена вместо подтверждений (кроме удаления) · уточняющий вопрос + быстрые кнопки · транскрипт до ответа · текст всегда · честные баннеры · тёмная тема по системе · мобильный вид первым.
- **Ошибки:** 401 → экран входа · 429 → «Повторить через N с» по `Retry-After` · «Сервер занят» → текст в ленте · сеть → красный баннер, автопроверка 5 с · 3 с → «Думаю дольше обычного…» · 20 с → ошибка.
- **Безопасность:** httpOnly + secure + samesite=strict cookie · CSP только `'self'` · шрифты локальные (`fonts.css`) · worklet отдельным файлом · `microphone=(self)` · без iframe · SW не кэширует API.
- **ТЗ:** «страница с кнопкой записи, историей и ответом» — есть; сверху — карточки, отмена, панель, звук, режимы, PWA, баннеры, мок.
- **Слабые места:** слепой тест ещё впереди (26–27.10) · iPhone после паузы > 15 с · нет «Повторить» для голоса · `check:contract` не в CI · нет автотестов фронта · нет ручного переключателя темы.
- **Демо с телефона:** напоминание → карточка «Новая» → «Отменить» → встреча без времени → «В три» → шторка «Сегодня» → без звука + текст.

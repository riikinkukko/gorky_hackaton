## 1. Зачем этот слой и где он стоит

```
голос → STT (voice/) → текст ─┐
                      текст ──┴→ Orchestrator (dialog/orchestrator.py)
                                   │ strip_hesitations()  — убирает «э-э…»
                                   ▼
                                 NLU.parse(text, state, now) → Command   ← МЫ ЗДЕСЬ
                                   ▼
                                 DialogManager → домен → хранилище → AssistantReply → TTS
```

**NLU** (Natural Language Understanding, «понимание естественного языка») превращает фразу в структурированную команду. На входе — текст (после распознавания речи или набранный руками), текущее состояние диалога `DialogState` и «сейчас» `now` с часовым поясом. На выходе — объект `Command` из `backend/app/contracts.py`. Интерфейс описан там же: `class NLU(Protocol): async def parse(self, text, state, now) -> Command`.

NLU **ничего не сохраняет и не ищет**. Он только понимает. Создавать записи, искать цель, проверять конфликты и задавать уточняющие вопросы — работа диалога (`app/dialog/`) и домена.

### 1.1. Что лежит в `Command` (контракт v1.2)

| Поле | Что это |
|---|---|
| `intent: Intent` | Намерение (интент): `create_item`, `list_items`, `search_items`, `update_item`, `complete_item`, `delete_item`, `undo`, `confirm`, `reject`, `smalltalk`, `unknown` |
| `slots: Slots` | Параметры команды («слоты»), см. ниже |
| `confidence: float` | Уверенность 0…1. От неё зависит, звать ли LLM и спрашивать ли подтверждение |
| `source` | Кто разобрал: `"rules"` (правила), `"llm"`, `"fallback"` (запасной разбор правилами, когда LLM не помог) |
| `raw_text` | Текст, который реально разбирался. Это уже **нормализованный** текст (после `asr.py`) |

**`Slots`** — все параметры:

| Слот | Пример | Комментарий |
|---|---|---|
| `type` | `task` / `meeting` / `reminder` | Тип записи (`ItemType`) |
| `title` | «Позвонить Ивану» | Название без даты, времени и слов «напомни/поставь» |
| `when` | `TimeSpec` | Когда (для create — время записи, для list/search — период, для update — где запись сейчас) |
| `duration_min` | 30 | Длительность в минутах |
| `participants` | `["Иван"]` | Люди в именительном падеже |
| `organization` | «Орбита» | Компания |
| `recurrence` | `FREQ=WEEKLY;BYDAY=MO` | Повтор в формате RRULE (стандарт iCalendar) |
| `query` | «техническое задание» | Тема для поиска: леммы с раскрытыми синонимами |
| `tense` | `past` / `future` / `any` | «Старую встречу» → `past` |
| `status` | `open` / `done` | «Выполненные задачи» |
| `target` | `ItemRef` | На какую запись ссылаются (для update/complete/delete) |
| `new_when`, `new_title` | | Новое время или название при переносе/переименовании |

**`TimeSpec`** — результат разбора даты:

| Поле | Смысл |
|---|---|
| `text` | Исходная фраза времени: «в пятницу в 11» |
| `start`, `end` | Начало и конец, всегда с часовым поясом. `end` у периода — **исключающая** граница |
| `has_time` | Время названо (False — только дата, «в пятницу») |
| `has_date` | Дата названа явно. «в три» → `has_date=False, has_time=True` |
| `is_period` | Это период («на следующей неделе», «сегодня» в вопросе) |
| `ambiguous` | Нужен уточняющий вопрос («на следующей неделе» при создании, «31 ноября», «в обед») |

**`ItemRef`** — ссылка на запись: `pronoun=True` («её», «эту»), `description` («встречу с Марией»), `item_id` (уже известный id, например после «вторую» в ответе на «Какую именно?»). Служебные метки `__last__` («последнюю задачу») и `__all__` («все встречи на завтра») задаются константами `MARK_LAST`/`MARK_ALL` в `router.py`.

## 2. Конвейер по шагам

Склеивается всё в двух местах:

- **`build_nlu()`** в `backend/app/nlu/__init__.py`. Читает настройки (`LLM_PROVIDER`, `NLU_LLM_TIMEOUT`, `NLU_RULES_THRESHOLD`, `NLU_ASR_NORMALIZE`, ключи GigaChat/Yandex), создаёт LLM-клиент и возвращает `HybridNLU`. Вызывается из `app/container.py`, если `NLU_IMPL=real`.
- **`HybridNLU.parse()`** в `backend/app/nlu/service.py`. Здесь сам порядок шагов.

```
HybridNLU.parse(text, state, now)
  0. normalize_transcript()      nlu/asr.py         — чистим транскрипт
  1. context.answer()            nlu/context.py     — это ответ на уточнение?
  2. router.route()              nlu/router.py      — правила; confidence ≥ 0.85 → готово
  3. _parse_llm()                nlu/llm/*          — LLM, если подключён (таймаут 6 с)
  4. router.fallback()           nlu/router.py      — запасной разбор, source="fallback"
```

### Шаг −1 (до NLU). `dialog/normalize.py: strip_hesitations()`

Вызывается в `DefaultOrchestrator.handle()` **до** `nlu.parse`. Убирает только незначащие звуки и паузы: «э», «э-э» (где угодно), «эм», «мм», «хм», «а-а» (только в начале фразы или между паузами, иначе это может быть буква аббревиатуры: «си ар эм» = CRM), многоточия. Слова-паразиты («ну», «короче») **не трогает**, потому что «ну да» — согласие. Если после чистки ничего не осталось, возвращает исходный текст.

В этом же файле есть `clean_title()` и `guard_title()`. Это последняя страховка названия в диалоге (`dialog/manager.py`): если в названии осталось «что», мат, время, обрывок «встреча с» или повтор, диалог не создаёт запись, а переспрашивает.

### Шаг 0. `nlu/asr.py: AsrNormalizer.normalize()`

Порядок внутри `normalize()`:

1. `normalize_acronyms()` — «срм», «си ар эм» → «CRM», «тэ зэ» → «ТЗ», также SMS, PDF, HR, API.
2. `strip_hesitations()` (своя, в `asr.py`) — «э-э», «эм», «мм», «хм», «ну короче», «короче говоря», «это самое», «так сказать», «как бы», «в общем».
3. `normalize_time()` — «в 15 00», «15.00», «15-00» → «15:00»; «пятнадцать ноль ноль» → «15:00»; «в девять сорок пять» → «в 9:45». «пять человек» и «в два раза» не трогает.
4. `_entities()` — исправляет искажённые сущности по словарю: «с арбитой» → «с Орбитой», «с и ваном» → «с Иваном», «созвон вектором» → «созвон с Вектором». Сравнение идёт по фонетическому ключу `phonetic_key()` (оглушение б→п, в→ф…; редукция гласных о→а, е/я/ы→и) и расстоянию Левенштейна (число правок между словами): 0 для слов короче 5 букв, 1 — от 5, 2 — от 9. Обычные словарные слова («лектор») не исправляются.

Словарь — люди, организации и темы из `synonyms.yml`. Есть механизм подмешивания сущностей из записей пользователя (`RepoEntitySource`, метод `HybridNLU.attach_repository(repo)`, кэш 5 минут), **но в текущем `app/container.py` этот метод не вызывается**. Работает только базовый словарь.

Если текст изменился, в лог `app.nlu` пишется строка `asr session=… original=… → text=… fixes=…`. Выключается переменной `NLU_ASR_NORMALIZE=false`. Скорость по докстрингу — около 0,2 мс на фразу.

### Шаг 1. Ответ на уточнение. `nlu/context.py: ContextResolver.answer()`

Когда диалог задал вопрос, он кладёт в `state.awaiting` его вид, а в `state.pending` — недоделанную команду. Значения `awaiting`: `"time"`, `"date"`, `"datetime"`, `"title"`, `"target"`, `"confirm_conflict"`, `"confirm_delete"`.

- `time/date` → `_time_answer()`: «в три», «давай на 16:30», голое «три» (к нему приписывается «в »). Время сливается с известной датой функцией `merge_when()`: «завтра» + «в три» → завтра 15:00. Если кроме времени есть ещё слова, это, скорее всего, новая команда, и возвращается `None`. Обрезанный ответ («ри») возвращает pending без изменений, чтобы диалог переспросил.
- `title` → название из ответа, если ответ не похож на новую команду (`_looks_like_new_command`: правила дают list/search/create/update/delete/complete с уверенностью ≥ 0.9).
- `target` → «вторую», «последнюю» → `ItemRef(item_id=state.last_item_ids[i])` (таблица `_ORDINALS`), иначе описание словами.
- `confirm_*` → `CONFIRM` / `REJECT`. При конфликте («это время занято») понимает «на час позже» (`_shift_answer`) и новое время. «Всё равно», «оставь» (`_KEEP_ORIGINAL`) → `CONFIRM`.
- «нет», «отмена» при любом ожидании → `REJECT`.

Уверенность ответов: время — 0.95, название — 0.9, цель — 0.85, да/нет — 0.95. Полноценная новая команда («Что у меня сегодня?») перебивает ожидание.

### Шаг 2. Правила. `nlu/router.py: RuleRouter.route()`

`route()` → `_preclean()` → `_route()` → контекстные поправки.

**`_preclean()`** — подготовка фразы (живые тесты 22–24.10):
- убирает приветствия (`_GREETING_LEAD`), мат (`PROFANITY`), сленг в начале (`_LEAD_SLANG`: «слышь», «короче», «блин»…);
- чинит обрезанное первое слово (`_fix_first_cut`, словарь `_FIRST_CUT`): «кажи» → «покажи», «мни» → «напомни», «речу» → «встречу». Короткие обрезки, совпадающие с настоящими словами («то» → «что»), чинятся только в контексте (`_FIRST_CUT_CTX`);
- снимает вежливые обёртки: `_polite_to_command` («можешь перенести…?» → «перенести…», только перед глаголом совершенного вида) и `_WRAPPERS` («не могли бы вы», «подскажи», «хорошо бы»…);
- убирает повторы («встреча встреча встреча»);
- применяет самопоправки (`_self_correction`, маркеры `_SELF_CORR`: «ой нет», «а нет», «то есть», «вернее», «хотя нет»…). Из части до маркера вырезается выражение того же вида, что после: дата → дата, время → время, «с Иваном» → «с Марией». Если дат нет — заменяется ближайшее существительное;
- вырезает идиомы и мусор (`GARBAGE`: «после дождичка в четверг») и слова неуверенности (`HEDGES`: «наверное», «может быть»). Если такие слова были, ставится `penalty=True`.

**`_route()`** — дерево решений, порядок важен:
1. Обрезанное «Перенеси» (`STUB_UPDATE`: «неси», «еси», «реси»… + ссылка на запись) → `update` с уверенностью не выше `STUB_CONF = 0.6`.
2. Да / нет / отмена (`YES`, `NO`, `UNDO`). «отмена» без ожидания → `UNDO`, при ожидании → `REJECT`.
3. «ой нет, я про понедельник» (`_ABOUT_DATE`) → повтор прошлого списка с новой датой.
4. Поправка прошлой команды (`_correction`): «нет, в 11».
5. Бессмыслица (`NONSENSE`: «алло, слышно меня?», «бла-бла») → `smalltalk`. Справка, приветствие → `smalltalk`. Погода, курс валют, такси (`OUT_OF_SCOPE`) → `unknown`.
6. Даты: `self.dates.extract(t, now, "period")`.
7. Вопрос ли это (`is_question`): «?» в конце, `QUESTION_START` («что», «какие», «покажи»…), `QUESTION_ANY` («что будет», «какие у меня»).
8. Продолжение прошлой команды (`_follow_up`): «А на следующей неделе?», «а встречи?», «А с Марией?». Работает только после `list`/`search` (берёт `state.last_command`).
9. Неявный перенос (`_implicit_update`: «было бы удобнее в воскресенье», «…давай на восемь»).
10. Глаголы: `COMPLETE` («отметь», «я сделал») → complete, `DELETE` → delete, `UPDATE` («перенеси», «сдвинь») → update. Сравнивается позиция глагола с позицией глагола создания (`_pos`), побеждает более ранний. Вопрос никогда не становится update/delete.
11. Вопрос с датой без темы → `list` («чё там у меня на завтра»). С темой, человеком или компанией → `search` («Какие встречи с Иваном были в прошлом году?»). `SEARCH_START` («найди», «когда», «вспомни») → `search`.
12. Создание: `CREATE_TRIGGER` («напомни», «поставь», «добавь», «запиши»…) → `_create(…, 0.92)`; фраза начинается с «встреча/созвон…» (`MEETING_START`) → 0.85; «нужно/надо» или «в четверг … встреча» (`_declares_meeting`) → 0.85 (0.75 без даты); дата+время без глагола («в субботу в 12 день рождения Ани») → 0.8; инфинитив («купить хлеб») → 0.75.
13. Ничего не подошло → `None` (дальше LLM или fallback).

**Как считается confidence.** Это **не вероятность модели**, а число, жёстко заданное для каждой ветки дерева по тому, насколько ветка надёжна:

| Ситуация | confidence |
|---|---|
| да / нет / отмена | 0.95 |
| пустая фраза из паразитов → unknown | 1.0 |
| smalltalk | 0.9–0.95 |
| create с глаголом-триггером | 0.92 |
| create «встреча …» в начале, «нужно …», «в четверг … встреча» | 0.85 |
| create дата+время без глагола | 0.8 |
| create «купить хлеб» (только инфинитив) | 0.75 |
| list с периодом / без периода | 0.92 / 0.8 |
| search обычный / вопрос с темой / вопрос без темы | 0.9 / 0.86 / 0.75 |
| update/complete/delete с целью / без цели | 0.9 / 0.6–0.7 |
| продолжение («А на следующей неделе?») | 0.9 |
| **штрафы:** неуверенность или мусор во фразе, в названии остались слова времени (`TIME_WORDS`), два времени во фразе, «две пары» (`MULTI_ITEMS`) | не выше `PENALTY_CONF = 0.7` |
| обрезанное «неси …» | не выше `STUB_CONF = 0.6` |

**Порог `NLU_RULES_THRESHOLD = 0.85`** (по умолчанию в `build_nlu`). Сравнение `rule.confidence >= self.rules_threshold`: при 0.85 правила ещё принимаются, при 0.84 — уже нет. Штрафы специально ставят уверенность ниже порога: в сомнительных фразах решает LLM (если он есть).

Тот же порог 0.85 использует диалог: `SAFE_CONFIDENCE = 0.85` в `dialog/manager.py`. Если цель берётся из контекста («её», «эту») и уверенность ниже или в `last_item_ids` несколько записей — действие выполняется только после подтверждения (`_risky()`).

**После `_route()`** в `route()` выполняются:
- `_date_from_context()`: «Покажи встречи на понедельник» → «добавь ещё созвон в три» → дата понедельника;
- `_there_from_context()`: «оттуда», «туда же» → день из прошлого списка;
- пустой поиск («найди найди») → `unknown` 0.6.

### Шаг 3. LLM. `nlu/llm/`

LLM вызывается, **только если** правила вернули `None` или уверенность ниже порога **и** LLM подключён.

**Провайдеры** (все за общим интерфейсом `LLMClient` в `llm/base.py`: метод `complete_with_tools(messages, tools) -> ToolCall | None`):

| Файл | Провайдер | Детали |
|---|---|---|
| `llm/gigachat.py` | `GigaChatClient` (Сбер) | OAuth-токен по `GIGACHAT_CREDENTIALS`, кэшируется до истечения (минус 60 с), при 401 обновляется один раз. `POST /chat/completions` с `functions`, `function_call: "auto"`, `temperature: 0.1`, `max_tokens: 400`. Модель `GIGACHAT_MODEL` (по умолчанию `GigaChat-2`), scope `GIGACHAT_API_PERS`, `GIGACHAT_VERIFY_SSL` — true/false/путь к сертификату Минцифры |
| `llm/yandex.py` | `YandexGPTClient` | Foundation Models API v1, `tools`, ответ в `toolCallList`. `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, модель `yandexgpt-lite`, `temperature 0.1`, `maxTokens 400` |

Выбор — `LLM_PROVIDER=gigachat | yandex | rules`. Любое другое значение (например, `ollama`, хотя оно упомянуто в комментарии `config.py`) в `build_nlu` не обрабатывается и даёт работу только на правилах. Если ключ не задан, конструктор клиента бросает `ValueError`, `build_nlu` пишет предупреждение «LLM … не настроен — работаем на правилах» и продолжает без LLM.

**Function calling** (вызов функций): модели передаются описания функций, и она отвечает не текстом, а выбором **одной** функции с аргументами в JSON. Модель не пишет свободный ответ пользователю, а заполняет форму.

**Схема инструментов — `llm/tools.py`, список `TOOLS`:** `create_item`, `list_items`, `search_items`, `update_item`, `complete_item`, `delete_item`, `smalltalk`. Главная деталь: в аргументах **нет дат**, только текст времени — `when_text`, `period_text`, `new_when_text` («Выражение даты/времени ДОСЛОВНО из фразы… Не вычисляй дату!»). Тип и `tense` — перечисления (`enum`). Цель — объект `target` с `ref ∈ {last, latest, all, description}`.

**Промпт — `llm/prompts.py`:** короткий системный промпт `SYSTEM` («задержка важнее красоты»). В него подставляются «сейчас», день недели и часовой пояс. Правила в промпте: не вычислять даты; title без даты и без «напомни/поставь»; «Напомни…» → reminder, «встреча/созвон/демо» → meeting; вопрос с периодом → list_items; «когда была…» → search_items; как ставить `tense`; «её/эту» → `target.ref=last`; имена в именительном падеже; текст может прийти из STT без пунктуации. `build_messages()` добавляет контекст: если ждём ответ на уточнение — «повтори ту же функцию с дополненными аргументами»; если есть `last_item_ids` — «"её/эту" означает её».

**Валидация** — `validate_call()`: аргументы прогоняются через Pydantic-модели (`CreateArgs`, `ListArgs`, `SearchArgs`, `UpdateArgs`, `TargetOnlyArgs`, `SmalltalkArgs`). Неизвестная функция → `ValueError`. Пустые строки превращаются в `None`, лишние поля игнорируются (`extra: ignore`). `title` — от 1 до 200 символов.

**Перевод в Command — `to_command()`.** Здесь модель окончательно лишается права считать:
- даты считает `RuleDateResolver.resolve(when_text, now, mode)`;
- `_merge_with_phrase()` — страховка: правила разбирают **исходную фразу** и дополняют недостающее (LLM вернул только дату — время берётся из правил, и наоборот). Добавлено после живого теста 22.10 («пара по английскому в 8 утра завтра» → без времени);
- если модель всё же вернула ISO-дату вместо фразы, её примет `_parse_iso()` в `dates.py`;
- `_tense()`: модель сказала `any`, а в фразе есть «старую» → `past` по правилам;
- `sanitize_title()` из `router.py` чистит название, `ents.normalize_person()` ставит имена в именительный падеж, `ents.expand_query()` раскрывает синонимы;
- у всех команд из LLM `confidence=0.85`, `source="llm"`.

**Повтор (ретрай)** — `_parse_llm()`, до 2 попыток:
- модель ответила текстом без функции → повтор с сообщением `retry_message("ответ без вызова функции")`;
- невалидные аргументы → повтор с текстом ошибки Pydantic (до 500 символов);
- после второй неудачи → `None` → fallback;
- если модель выбрала `smalltalk`, хотя диалог ждёт ответа на уточнение, → `None`: правила здесь надёжнее.

**Таймаут** — `NLU_LLM_TIMEOUT` (по умолчанию 6 с). `asyncio.wait_for` охватывает **весь** `_parse_llm` вместе с ретраем. То же значение передаётся в HTTP-клиент. При `TimeoutError` или `LLMError` (сеть, авторизация, неожиданный формат) — предупреждение «LLM недоступен, фолбэк на правила» и переход к шагу 4.

### Шаг 4. Fallback. `RuleRouter.fallback()`

Лучшая догадка правилами вместо отказа, всегда с `source="fallback"`:
- `route()` вернул команду (даже с низкой уверенностью) → она же, но с пометкой fallback. Если это пустой поиск → `unknown` 0.3;
- `route()` вернул `None`: вопрос с датой → `list` (вопрос с датой **никогда** не становится созданием); просто дата → `create` 0.5; два и больше слов → `search` 0.4; иначе `unknown` 0.3.

**Важно:** без LLM каждая фраза, на которой правила не уверены, уходит в fallback. Поэтому на стенде `source=fallback` — нормальная картина, а не авария.

## 3. Даты: `nlu/dates.py`, класс `RuleDateResolver`

Два метода:
- `resolve(text, now, mode)` → `TimeSpec` (протокол `DateResolver` из контракта). Если ничего не найдено — пробует ISO, иначе `TimeSpec(ambiguous=True)`.
- `extract(text, now, mode, prefer_past=None)` → `DateParse(spec, has_date, spans, deadline, recurrence)`. Ищет время **внутри целой фразы** и возвращает позиции найденного (`spans`) в исходном тексте, чтобы роутер мог вырезать дату из названия (`remove_spans()`).

`mode="point"` — момент (для создания), `mode="period"` — интервал (для списков и поиска). `now` обязан быть с часовым поясом, иначе `ValueError`.

### 3.1. Как устроен разбор

1. `text.py: normalize()` разбивает фразу на токены и помнит позицию каждого в оригинале (`NormText.orig_span`). Числа словами → цифры («двадцать седьмого» → «27 числа»), «полчетвёртого» → «половине 4», «полчасика» → «30 минут», «15-го» → «15 числа», «две тысячи двадцать шестого» → «2026», опечатки дат («севодня» → «сегодня», `fix_date_typo`, только для слов не из словаря pymorphy).
2. Правила по очереди заполняют структуру `_Parts`. Каждое правило «занимает» свой фрагмент (`p.take`), следующее его не трогает (`p.free`): `_recurrence` → `_relative` → `_deadlines` → `_periods` → `_day_words` → `_weekdays` → `_explicit_dates` → `_times` → `_dayparts`.
3. `_combine()` собирает `TimeSpec` по приоритету: невалидная дата → дедлайн → «через N» → день недели → период → время без даты → день (± время).

### 3.2. Политики (`docstring` модуля и `_apply_pm`)

| Фраза | Результат | Где в коде |
|---|---|---|
| «в 3», «в 5» (час 1–7 без уточнения) | 15:00, 17:00 | `_apply_pm`: `not qualified and 1 <= hour < 8 → +12` |
| «в восемь», «в 10» | 08:00, 10:00 | час ≥ 8 считается уточнённым (`hour_qualified = h >= 8`) |
| «в 10 вечера» | 22:00 | daypart «вечер» → +12 |
| «в 12 ночи» | 00:00 следующего дня | `_combine`: полночь «сегодня» → завтра |
| «утром / днём / вечером / ночью» | 09:00 / 13:00 / 19:00 / 23:00 | `DAYPART_TIME` |
| «после обеда» | 15:00 | `_dayparts` |
| «в обед» (создание) | окно 12:00–14:00, `ambiguous=True` | диалог предложит время |
| «в пятницу» | ближайшая будущая пятница; если сегодня пятница и время не прошло или не указано — сегодня | `_weekday_date` |

### 3.4. Прошлое: `prefer_past` и `_PAST_MARKERS`

Если в фразе есть маркер прошлого, неоднозначные даты трактуются назад. `extract()` при `prefer_past=None` сам ищет `_PAST_MARKERS`: «был/была/было/были», «прошл…», «вчера», «позавчера», глаголы «ставил, звонил, встречал, созванивал, обсуждал, отправлял, делал, проводил, писал…» и прилагательные из `PAST_ADJ` («старую», «прошедшие», «давнюю», «ранние» — но не «ранним утром», «прежние», «минувшие»).

С `prefer_past=True`:
- «в понедельник» → прошедший понедельник: «старую встречу в понедельник» → 2026-10-19;
- «в ноябре» → прошлогодний ноябрь: «что было в ноябре» → 2025-11-01;
- «15 марта» без года → в прошлом году, если дата ещё не наступила;
- «на днях» → прошедшая неделя.

При создании записи прошлое не предпочитается: `RuleRouter._create_dates()` вызывает `extract(..., prefer_past=False)`. Слова «вчера», «в прошлый раз» при наличии другой даты считаются контекстом, а не временем записи.

`has_date / has_time / is_period / ambiguous` — смысл в таблице раздела 1.1. Хелпер для диалога: `has_explicit_date(text, now)` — была ли во фразе дата (нужен при переносе «на 19:00», чтобы сохранить день записи).

## 4. Сущности и словари

### 4.1. `nlu/entities.py: EntityNormalizer`

- **Леммы** (начальная форма слова: «Иваном» → «иван») — через `pymorphy3` (морфологический анализатор русского языка). `lemmas(text)` возвращает список `Lemma(orig, lemma, key, start, end, is_name, capitalized)`; `key` — без «ё», для сравнения. Есть таблица исправлений `_LEMMA_OVERRIDES` («демо», «тз», «деньгам» → «деньги», «планерку» → «планёрка»).
- **Имена** — `_is_name()`: тег `Name` у pymorphy. Имена-омонимы обычных слов (`_NAME_HOMONYMS`: Роман, Вера, Надежда, Любовь, Марина, Слава…) считаются именем, только если написаны с заглавной и не в начале фразы. Для незнакомых слов pymorphy «угадывает» имя («хакатону»), такому не верим. STT рвёт имена: «с и ваном» → склеиваем, если получилось известное имя. `people()` возвращает имена в каноническом виде («Иван»).
- **Организации** — `organizations_in()`: точное совпадение по всем падежным формам (`_org_forms`) или нечёткое (`_fuzzy`, Левенштейн ≤1/≤2) после предлога «с, у, для, от, к…». Сначала проверяются организации, потом имена, иначе «с Альфой» станет человеком «Альф».
- **Тип записи** — `item_type()`: по словам из раздела `types` словаря. Слово после управляющего предлога («подготовиться **к встрече**», «итоги **после** встречи») не считается: это не встреча.
- **Время запроса** — `tense()`: `past` по `_OLD_ADJ` («старую», «прошедшие», «предыдущие»), `PAST_ADJ`, «был/раньше/прошл…/когда-то/последний раз» или глаголу прошедшего времени (проверка pymorphy, список исключений `_PAST_FALSE`); `future` по `_NEW_ADJ`/`_FUTURE_RE` («будет», «предстоящие», «ближайший», «следующий», «скоро»); иначе `any`.
- **Запрос для поиска** — `expand_query()`: убирает имена, организации, стоп-слова (`STOP_LEMMAS`, включая «старый», «прошедший» — это время, а не тема) и общие слова типа («задача», «дело» — `GENERIC_TYPE_LEMMAS`), склеивает фразы-синонимы, раскрывает `expand`, приводит глаголы к канону.

### 4.2. `nlu/synonyms.yml` — правится без кода

| Раздел | Что делает | Примеры |
|---|---|---|
| `phrases` | разговорный вариант → каноническая тема | «мобилка», «приложение», «апп» → «мобильное приложение»; «тз», «тэ зэ», «техничка» → «техническое задание»; «кп» → «коммерческое предложение»; «срм», «црм» → «CRM»; «презуха», «слайды» → «презентация» |
| `expand` | слово дополнительно ищет другие | «деньги», «финансы», «бабки» → «бюджет смета»; «оплата» → «бюджет смета акт»; «документы», «бумаги» → «договор акт протокол» |
| `verbs` | разговорный глагол → глагол из заголовков | «набрать», «прозвонить» → «позвонить»; «скинуть», «переслать» → «отправить»; «глянуть» → «проверить»; «перетереть» → «обсудить» |
| `types` | слова, задающие тип | meeting: встреча, созвон, пара, демо, планёрка, синк…; reminder: напоминалка…; task: задача, таск, поручение… |
| `organizations` | компании из CSV | Альфа, Вектор, Север, Орбита, Маяк, Партнёр, Пульс, Старт |
| `people` | имена из CSV | Алексей, Анна, Дмитрий, Елена, Иван, Максим, Мария, Наталья, Ольга, Сергей |

Сравнение идёт по леммам, поэтому «мобилку», «мобилкой» и «мобилка» — одно и то же.

### 4.3. `nlu/text.py`

Нормализация для правил (см. 3.1): токены с позициями в оригинале, числительные словами → цифры, порядковые → «N числа», «пол-» + порядковое → «половине N», разговорные «часик», «выхи», опечатки в словах дат. Там же `simple_norm()` (нижний регистр, ё → е) и `_lev()` (расстояние Левенштейна), которыми пользуются остальные модули.

### 4.4. Прочее понимание в роутере

- **Самопоправки**: `_self_correction()` (см. шаг 2). «в среду ой нет в четверг отправить договор» → «в четверг отправить договор».
- **Вежливые обёртки**: `POLITE` + `_polite_to_command()`, `_WRAPPERS`. «Ты можешь записывать встречи?» (несовершенный вид) — это вопрос о возможностях (`CAPABILITY`) → smalltalk, а не команда.
- **«её / эту»**: регулярка `PRONOUN`. Роутер ставит `target=ItemRef(pronoun=True)` и ничего не ищет. Какая запись имеется в виду, решает диалог по `state.last_item_ids` (`dialog/targets.py`). Если записей в контексте несколько или уверенность ниже 0.85 — с подтверждением (`_risky`).
- **Сдвиг**: `parse_shift("на час позже")` → `+60`, «на полчаса пораньше» → `−30`, «на пару дней» → `+2880`. При переносе со сдвигом `new_when.start=None`, минуты считает диалог через `parse_shift(new_when.text)`.

Разбор по шагам:

- **№1.** `CREATE_TRIGGER` нашёл «напомни» → `_create(…, 0.92)`. Даты: «завтра» (`_day_words`) + «в 10 утра» (`_times`, daypart «утро»). Есть «напомн» → reminder. `_make_title()` вырезает «напомни мне», дату и время. «Ивану» → лемма имени «Иван». Первый вызов в процессе занял около 170 мс (прогрев pymorphy и регулярок), дальше — единицы миллисекунд.
- **№2.** Глагола создания нет. Сработал `_declares_meeting`: после вырезания даты остаётся «у меня встреча…», начало совпадает с `MEETING_HEAD` → 0.85, ровно на пороге, поэтому LLM не нужен. «в 11»: час ≥ 8, без +12. Четверг — ближайший будущий (29.10). «дизайнер» — не имя, поэтому `participants` пуст, но слово сохранено в названии.
- **№3.** «Поставь задачу» — явная задача (`_EXPLICIT_TASK`), так что тип не превратится во встречу. Дедлайн «до конца недели» → воскресенье 23:59.
- **№4–6.** Вопрос + дата без темы → `_list()`. «встречи» → `type=meeting` (`_type_filter`). Три разные формулировки дают один интент и один период.
- **№7.** `SEARCH_START` («когда») → `_search()`. «была» → `tense=past` (`EntityNormalizer.tense`). Хранилище отфильтрует будущие встречи.
- **№8.** Глагол `UPDATE` + `PRONOUN` → цель из контекста. Сам сдвиг считает диалог.
- **№9.** `_self_correction()` до разбора вырезал «в среду» (дата → дата). Дальше: дата + инфинитив в начале → `_create(…, 0.85)`.

## 6. Почему так устроено

**LLM только понимает, а не считает.** Модели ошибаются с днями недели, переходом через полночь, «через N часов», високосными годами, «31 ноября». Детерминированный резолвер (одинаковый вход → одинаковый результат) покрыт тестами (`tests/nlu/test_dates.py` и другие) и даёт воспроизводимый результат при замороженном `now`. LLM выбирает функцию и дословно выписывает фразу времени, а дальше работает наш код (`to_command`).

**Почему правила первыми:**
- **Скорость.** На 100 фразах golden правила дают p50 ≈ 2,3 мс, p95 ≈ 5 мс (замер этим скриптом). У облачной LLM вызов занимает порядка секунд (поэтому таймаут 6 с). В отчёте `backend/eval/report.md` задержка всего хода — 0,01 с p50 / 0,04 с p95.
- **Цена.** Вызов правил бесплатен, а запросы к LLM оплачиваются.
- **Предсказуемость.** Одна и та же фраза всегда разбирается одинаково, ошибку можно закрепить тестом.
- **Работа без сети.** Нет ключа, нет интернета, лежит API — ассистент работает.

**Что происходит без ключа.** `LLM_PROVIDER` по умолчанию `rules` (`config.py`). `HybridNLU.llm = None`, шаг 3 пропускается, неуверенные фразы идут в fallback. **Все метрики проекта получены именно так**: в `backend/eval/report.md` — «nlu=real:rules», 100/100 golden; в `qa/adversarial/BASELINE.md` — «только правила, без LLM», 92% (535/583).

**Сколько фраз ушло бы в LLM, если его включить** (мой замер, правила с уверенностью < 0.85 или `None`): golden — 2 из 100 (2%), однофразовые каверзные реплики `qa/adversarial/*.jsonl` — 89 из 509 (17%).

**Где в логах видно, кто разобрал:**
- `backend/app/api/chat.py`, логгер `turn`: `turn session=… user=… text='…' → intent=… source=rules|llm|fallback action=… reply='…'`. Команда: `docker compose logs api | grep turn`.
- Логгер `app.nlu`: `asr session=… original=… → text=… fixes=…`, «LLM недоступен, фолбэк на правила: …», «LLM вернул невалидный вызов (N): …», «LLM gigachat не настроен (…) — работаем на правилах».
- В ответе API — `reply.debug`: `intent`, `source`, `confidence`, `slots`, `awaiting`, `latency_ms.nlu` (собирает `DefaultOrchestrator.handle`).

## 8. Честные слабые места сейчас

1. **Продолжения без явной команды.** «а давай лучше в субботу», «пусть повторяется каждую неделю». В `README.md`: на каверзных репликах ось «контекст» проходит в **74%** случаев. Что выдаёт NLU прямо сейчас (запуск после «Поставь встречу с Иваном завтра», `last_item_ids=[42]`):
   - «а давай лучше в субботу» → `create_item`, title «Лучше», fallback 0.5 (правильно — перенос);
   - «пусть повторяется каждую неделю» → `create_item`, title «Пусть повторяется», `recurrence=FREQ=WEEKLY`, fallback 0.8 (правильно — update с повтором).

   Причина: `_follow_up` умеет продолжать только `list`/`search`, а для create/update контекст понимается лишь по явным глаголам и местоимениям. С LLM обе фразы ушли бы в модель (уверенность < 0.85), но это не измерено.
2. **Бессмыслица иногда уходит в поиск.** «фиолетовый слон танцует» → `search_items`, query «фиолетовый слон танцевать», fallback 0.4. Пользователь услышит «не нашёл», а не «не понял». Ветка в `fallback()`: два и больше слов → поиск.
3. **Годы словами.** «пятнадцатого марта двадцать пятого года» → нормализуется как «15 марта 25 числа года» и даёт **2027-03-15** (неверно). «в две тысячи двадцать седьмом году» → не разбирается (`ambiguous`). Работают «две тысячи двадцать восьмого» после даты и год цифрами.
4. **Словарь сущностей пользователя не подключён.** `attach_repository()` нигде не вызывается, поэтому `asr.py` исправляет только имена и компании из `synonyms.yml`.
5. **Часовой пояс один на развёртывание.** «Сейчас» берётся из `Settings.now()` по `DEFAULT_TZ` (Europe/Moscow). В таблице `users` есть колонка `tz`, но в разборе она не используется.
6. **Ветка LLM не прогонялась на метриках.** Все цифры получены на правилах, LLM покрыт юнит-тестами на мок-клиентах.

## 9. Вопросы жюри и ответы

**1. Почему GigaChat?**
Доступен из РФ без обходных путей, хорошо понимает русский, поддерживает function calling, данные остаются в российской юрисдикции. Провайдер спрятан за интерфейсом `LLMClient` и меняется переменной `LLM_PROVIDER`: готов и YandexGPT (`llm/yandex.py`), а `rules` — работа вообще без модели.

**2. Что будет, если LLM недоступна?**
Ничего страшного. Ошибка сети или авторизации (`LLMError`) или превышение `NLU_LLM_TIMEOUT` (6 с) → `router.fallback()`, команда с `source="fallback"`. Без ключа LLM даже не создаётся. Все наши метрики получены с `LLM_PROVIDER=rules`.

**3. Как боретесь с галлюцинациями?**
Модель не пишет текст, а выбирает одну из 7 функций. Тип и время — перечисления (`enum`), аргументы проверяет Pydantic, невалидный ответ — один ретрай с текстом ошибки, потом правила. Даты модель не считает: только копирует фразу, считает `RuleDateResolver`. Правила перепроверяют исходную фразу (`_merge_with_phrase`, `_tense`). Название чистит `sanitize_title`, а в диалоге — `guard_title`. Удаление всегда с подтверждением, есть отмена.

**4. Почему не fine-tune (дообучение модели)?**
Нет данных: в CSV организаторов — записи, а не реплики пользователей. Дообучение дорого, долго и привязывает к одной модели. Наша задача — разметить фразу в фиксированную схему, а для этого хватает function calling с коротким промптом и правил. Улучшения делаются правкой словаря и тестом за минуты, а не переобучением.

**5. Как понимаете «её», «эту»?**
NLU ставит `target.pronoun=True` и не угадывает запись. Диалог берёт её из `state.last_item_ids` — записи, с которыми работали в прошлом ходе (`dialog/targets.py`). Если таких записей несколько или уверенность ниже 0.85, выполнения нет, ассистент переспрашивает (`_risky`, `SAFE_CONFIDENCE`). В LLM-промпт при наличии контекста добавляется «"её/эту" означает её».

**6. Как работаете с разными формулировками одного действия?**
Три уровня. Леммы pymorphy3 («Иваном», «Ивану» → Иван). Словарь `synonyms.yml` («мобилка» → мобильное приложение, «деньги» → бюджет и смета, «набрать» → позвонить). Регулярки-триггеры с десятками глаголов и вежливых форм. Пример: «Что у меня сегодня?», «Какие планы на сегодня?», «Покажи мои встречи на сегодня» дают один `list_items` с одинаковым периодом. Остаток закрывает LLM.

**7. Как с относительными датами?**
Детерминированный резолвер `nlu/dates.py` с явными политиками: «в 3» → 15:00, «в восемь» → 08:00, утром 09:00, вечером 19:00, ближайший будущий день недели, неделя пн–вс, «до конца недели» → вс 23:59, «31 ноября» → уточнение. «Сейчас» всегда передаётся параметром, поэтому результат воспроизводим.

**8. Как с часовыми поясами?**
Все `datetime` в контракте — с часовым поясом (`TimeSpec`: «Все datetime — с таймзоной»), без пояса резолвер падает с `ValueError`. В базе — `timestamptz`. Пояс сейчас один на развёртывание (`DEFAULT_TZ=Europe/Moscow`). Колонка `users.tz` есть, перевод «сейчас» на пояс пользователя — следующий шаг.

**9. Сколько стоит LLM?**
По экономической модели (`docs/pitch/JURY_QA.md`, п. 6.1) — около 20 ₽ в месяц на пользователя при 130 запросах и допущении, что роутер закрывает 40%. Фактически правила закрывают больше: в LLM ушли бы 2% golden-фраз и 17% каверзных. Значит, модель консервативна. Короткий промпт и `max_tokens=400` ограничивают расход на вызов.

**10. Сколько запросов уходит в LLM?**
Только те, где правила вернули `None` или уверенность < 0.85. Замер: 2 из 100 golden, 89 из 509 однофразовых каверзных реплик. Ретрай максимум один, то есть не больше двух вызовов на фразу.

**11. Как понимаете ошибки распознавания речи?**
`asr.py` до разбора: время («15 00» → 15:00), заминки, фонетическое сопоставление сущностей («с арбитой» → Орбита). Роутер чинит обрезанное первое слово («кажи» → «покажи», «неси» → перенос с подтверждением). Опечатки в датах («севодня») исправляет `fix_date_typo`.

**12. Что если пользователь передумал посреди фразы?**
«в среду ой нет в четверг отправить договор» → `_self_correction` убирает исправленную часть, получаем «в четверг отправить договор». Работает для дат, времени, людей и компаний («с Иваном, ой, с Марией»).

**13. Как отличаете вопрос от команды создания?**
Признаки вопроса: «?», начало «что/какие/покажи», «что будет / какие у меня» в любом месте. Вопрос никогда не становится update/delete, а в fallback вопрос с датой — всегда список. Исключение: «не забудь, что у меня в понедельник собеседование в 11» — создание (есть триггер и время).

**14. Откуда confidence, если нет модели?**
Это заданные вручную веса веток дерева правил (0.95 для «да/нет», 0.92 для «напомни…», 0.75 для голого «купить хлеб») и штрафы до 0.7 за неуверенность, мусор, время в названии. Порог 0.85: выше — отвечают правила, ниже — LLM или fallback, а диалог требует подтверждения для рискованных действий.

**15. Как проверяете качество?**
583 юнит-теста NLU, golden_eval 100/100 по всем метрикам (`backend/eval/report.md`), 583 каверзных сценария в `qa/adversarial` с оракулами: 92% проходят целиком, контрольные 30 свежих фраз — 25/30.

# storage/ — данные, импорт, поиск (зона чата 3)

## Зависимости

Уже в `backend/pyproject.toml`: `sqlalchemy[asyncio]`, `psycopg[binary]`, `alembic`, `pgvector`,
`pymorphy3`, `pymorphy3-dicts-ru`, `python-dateutil`, `pyyaml`; extra `embeddings`
(`sentence-transformers`) — только если `EMBEDDINGS_MODEL` ≠ `hash`. Образ базы:
`pgvector/pgvector:pg16` (расширения `vector` и `pg_trgm` создаёт миграция).

## Подключение (app/container.py)

```python
from app.storage import build_repository, build_search  # STORAGE_IMPL=postgres

repo = build_repository(settings)  # settings.database_url или env DATABASE_URL
search = build_search(settings, repo)  # та же база и тот же эмбеддер, что у repo
```

## Запуск

```bash
make migrate     # alembic -c app/storage/alembic.ini upgrade head
make seed        # python -m app.cli import-csv …/voice_assistant_events_1000.csv --user 1
# без docker, из backend/:
python -m app.cli import-csv ../data/voice_assistant_events_1000.csv --user 1   # ~3 с
python -m app.cli search "Когда у меня была встреча с Иваном?" --tense past --now 2026-10-21T14:00:00+03:00
make eval EVAL_ARGS="--min-recall 0.9"                               # метрики → stdout
pytest tests/storage                                                 # тесты, БД <name>_test
```

`--user` принимает id (`1` — демо-пользователь; строка в `users` создаётся при необходимости)
или имя. Импорт идемпотентен: повтор (например, на каждом старте API через `docker-entrypoint.sh`) сразу
пропускает загруженные строки без обогащения, `--replace` перезаливает.
Для первого пользователя id записей = id из CSV, поэтому id из `golden_eval.jsonl` совпадают
с базой. У следующих пользователей id новые, связь с CSV — через `items.source_ref = "csv:<id>"`.

## Схема (миграция `0001`)

| Таблица | Назначение |
|---|---|
| `users` | `name`, `tz`, `ics_token` (для ICS-фида) |
| `items` | поля `Item` из контракта + поисковые: `person_norm`, `organization_norm`, `search_text` (леммы + синонимы), `search_tsv` (генерируется: russian по заголовку + simple по леммам), `embedding vector(1024)`, `sort_at` (генерируется: `coalesce(starts_at, due_at)`), `source_ref`, `deleted_at` |
| `actions` | журнал действий для undo: `kind`, `item_id`, `before`/`after` (JSON `Item`) |
| `dialog_sessions`, `turns` | состояние сессии и лог ходов (метрики, отладка) |

Индексы: `(user_id, starts_at)`, `(user_id, due_at)`, частичный `(user_id, sort_at) WHERE deleted_at IS NULL`,
GIN по `search_tsv`, `person_norm`, `organization_norm`, GIN-триграммы по `title` и `search_text`,
HNSW (cosine) по `embedding`, уникальный `(user_id, source_ref)`.

Хранение времени: встреча — `starts_at`/`ends_at`; задача и напоминание — `due_at`
(`has_time=false`, если время не указано). Только tz-aware datetime: naive отклоняется с `ValueError`.

## Импорт CSV: что исправляется

Данные сделаны по ~25 шаблонам; разбор шаблонами (`enrich.py`) детерминирован, неизвестный
текст не теряется (тип по первому слову, сущности словарём). Итог на 1000 строк:
задачи 761, встречи 186, напоминания 53; исправлено 313 заголовков:

| Было | Стало | Строк |
|---|---|---|
| Позвонить Иваном · Отправить договор Марией · Подготовить вопросы для Натальей · Напомнить Анной про мобильному приложению · Обсудить договору с Алексеем | Позвонить Ивану · Отправить договор Марии · Подготовить вопросы для Натальи · Напомнить Анне про мобильное приложение · Обсудить договор с Алексеем | 300 |
| Созвон с Стартом · Подготовиться к встрече с Стартом | …со Стартом | 8 |
| Обсудить бюджет по бюджету | Обсудить бюджет | 5 |

`title_original` хранит исходник, `status=unknown`, `source=import`. Длительность: встреча 60 мин,
демо 30 мин; задачи и напоминания — точка во времени.

## Поиск (`ranking.py` — общий для PostgreSQL и памяти)

Один алгоритм на два хранилища. `ranking.py` (без SQLAlchemy) — разбор запроса, фильтры,
покрытие, уровни, порядок, «не нашёл». Отличается только источник кандидатов:
`search.py` (`HybridSearchEngine`, PostgreSQL) отбирает их индексами — FTS, триграммы, вектор;
`memory.py` (`InMemorySearchEngine`, он же `FakeSearchEngine` при `STORAGE_IMPL=memory`)
перебирает все записи. CSV в обоих случаях разбирает `enrich.csv_item` (те же заголовки,
люди, компании), поисковые поля считает `ranking.make_fields`. Совпадение выдачи — записи,
порядок, баллы — проверяет `tests/storage/test_search_parity.py` (эталонные и дополнительные
запросы, со слотами NLU, без NLU и только со структурными слотами).

Слова времени — «старую», «прошедшие», «давнюю», «ранние», «прежние» (прошлое), «будущие»,
«предстоящие» (будущее) — не тема запроса. Если NLU оставил `tense=any`, поиск берёт время
из них сам.


1. Фильтры из `Slots`: `type`, `participants`, `organization`, `status`, `tense` (или время из
   слов запроса), `when`. SQL-фильтры `search._filters` — двойник `ranking.passes_filters`.
   Имена и компании, которые NLU не выделил, достаются из текста (с опечаткой в одну букву:
   «с арбитой» → Орбита; разбитое STT имя «и ваном» → Иван).
2. Смысловые группы: леммы запроса без служебных слов и слов времени, каждая с синонимами
   (ТЗ = техническое задание, мобилка = мобильное приложение, деньги = бюджет/смета, КП, …);
   аббревиатуры по буквам («тэ зэ», «си ар эм») нормализуются.
   Словарь — `app/nlu/synonyms.yml` (ведёт чат 1; путь — `SYNONYMS_PATH`), своего у поиска нет:
   `phrases` — симметричные группы (двухсловные варианты склеиваются в токен канона:
   «тех задание» → `техническое_задание`); `expand` — только для запроса («деньги» → бюджет,
   смета); `verbs` — разговорный глагол к глаголу заголовков («звонил» → позвонить, «готовился»
   → подготовиться); `types` — мягкий приоритет типа; `organizations`, `people` — сущности.
   Файла нет — поиск работает без синонимов (предупреждение в логе). После правки словаря —
   `python -m app.cli reembed`, иначе в базе останется `search_text` по старому словарю.
3. Кандидаты внутри фильтров: объединение выдач FTS, триграмм и k-NN по эмбеддингу (без слияния по рангам — порядок задаёт шаг 5, `ranking.rank_matches`).
4. Покрытие: доля смысловых групп, найденных в записи (с учётом опечаток). Записи с покрытием
   ниже половины лучшего отсекаются. Если совпало только слово-тип («встреча»), а предмет
   («с дизайнером») — нет, ответ пустой: честное «не нашёл».
5. Порядок: покрытие → совпадение с типом из запроса («встреча», «созвон» → meeting) → время
   (past — свежие первыми, future — ближайшие, any — ближайшие к «сейчас»).

**score в выдаче** — уровень релевантности (покрытие запроса минус 0,01 за несовпавший тип), а не
позиция: у одинаково подходящих записей он одинаковый и вниз по списку не растёт. Порядок внутри
уровня задаёт поиск (past — свежие первыми, future — ближайшие). Если в лучшем уровне ≥ 5 записей,
нижние уровни не отдаются. Слова, которые NLU подставил из одного правила `expand`
(«деньги» → «бюджет смета»), считаются одним понятием «или».

Эмбеддер: по умолчанию `EMBEDDINGS_MODEL=hash` — локальный, без скачивания моделей (леммы +
синонимы + символьные триграммы, 1024 измерения). Настоящая модель — `EMBEDDINGS_MODEL=deepvk/USER-bge-m3`
(нужен `sentence-transformers`), затем `python -m app.cli reembed`.

## Репозиторий: семантика сверх контракта

- `create` игнорирует `item.id`, `created_at`, `updated_at` — их ставит база.
- `list_range` возвращает записи с моментом в `[start, end)`, встречи, пересекающие период,
  и повторяющиеся серии, начатые до `end` (развёртку делает домен: `expand_occurrences`).
- `find_overlaps` — встречи, пересекающие `[start, end)` (смежные не конфликтуют), задачи и
  напоминания со временем внутри интервала; повторяющиеся встречи разворачиваются.
- Журнал undo (контракт v1.1): `log_action(ActionRecord) -> id`, `get_action`, `mark_undone`;
  таблица `actions`, снимки `before` / `after` хранятся как JSON `Item` и читаются обратно в `Item`.
- Дополнительно: `get_or_create_user`, `get_many`.

## Метрики (`eval/`)

`run_eval.py` следует `golden_eval_format.md`: каждая строка в чистой копии данных (клон шаблонного
пользователя; шаблон — засеянный пользователь 1, если его импорт не тронут, иначе свежий импорт),
`history` проигрывается в той же сессии, сравнение в Europe/Moscow до минуты.
Режимы: по умолчанию `container` — `app.container.build_container(Settings())`, то есть fake или
real из `.env`. Хранилище `postgres`: строки изолированы клонами пользователя; `memory`: новый
контейнер с CSV на каждую строку (если `SEED_CSV` пуст, eval подставит CSV сам). Ещё:
`orchestrator` (явная фабрика), `http` (`/api/chat` + `X-Freeze-Now`), `search` (только поиск,
без NLU). Таблица всегда в stdout.

Пороги: `--min-recall 0.9` — критерий чата 3, проверяется отдельным коротким прогоном слоя
поиска на q19–q30 (PostgreSQL, без NLU), поэтому не зависит от того, какой NLU подключён;
`--min-recall-e2e` — сквозной Recall@5 из основной таблицы.
Recall@5 = |top-5 ∩ relevant| / min(5, |relevant|).

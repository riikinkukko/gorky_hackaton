# dialog/ + domain/ — диалог и бизнес-логика (чат 2)

## Что где

| Файл | Что делает |
|---|---|
| `dialog/__init__.py` | `build_orchestrator(*, settings, nlu, dates, repo, search)` — фабрика для `app/container.py` (`DIALOG_IMPL=real`) |
| `dialog/orchestrator.py` | `DefaultOrchestrator.handle(text, state, now)` — NLU → DialogManager → `AssistantReply` + `debug` (интент, слоты, задержки) |
| `dialog/manager.py` | `DialogManager`: слот-филлинг, уточнения, конфликты, подтверждение удаления, «отмена», undo |
| `dialog/normalize.py` | Убирает звуки-заминки («э-э», «эм,») и паузы («…») перед NLU; чистит названия создаваемых записей |
| `dialog/targets.py` | `TargetResolver`: «её», «встречу с Марией в субботу», выбор из нескольких |
| `domain/service.py` | `ItemService`: build / create / list_period / next_after / search / moved / complete / delete / undo |
| `domain/conflicts.py` | `ConflictChecker`: пересечения и ближайший свободный слот 08:00–21:00, шаг 15 мин |
| `domain/recurrence.py` | RRULE (dateutil): первое вхождение, развёртка в списках, «каждый понедельник» |
| `domain/responder.py` | Тексты ответов: абсолютная дата, падежи, группировка списков > 5 |
| `domain/ru.py` | Даты по-русски, числительные, творительный падеж имён, грубый стемминг |

Тестовые фейки — только в `tests/dialog/`: `scripted_nlu.py` (фраза → Command), `fake_storage.py` (репозиторий и поиск на CSV организаторов).

## Поведение

- **Обязательные слоты:** встреча — название + дата + время; напоминание — текст + дата-время; задача — текст.
  Нет названия встречи, но есть участник → «Встреча с Марией».
- **Ответ на уточнение** («в три») накладывается на известную дату («завтра») → чт 15:00.
  Новая полная команда во время уточнения бросает старую; «отмена» / «нет» выходят из сценария.
- **Конфликты:** встреча пересекается со встречей (интервал) или задачей со временем (точка) →
  «Поставить на 16:30 или всё равно на 15:30?». Принимает «да», «16:30», «всё равно…», другое время.
  Проверяется и при переносе.
- **Контекст:** после каждого ответа `state.last_item_ids` = записи, которые назвали вслух.
  «Её» без описания → они. Несколько кандидатов → «Какую именно?» (ответ: «вторую», «2», «с дизайнером»).
  Одинаковые записи (повторы в данных) → ближайшая будущая.
- **Удаление** — только после «да». **Undo** («отмени», кнопка) откатывает создание, перенос,
  выполнение, удаление (soft delete → restore).
- **Списки:** ≤ 5 — целиком; больше — количество, состав («2 встречи и 6 задач»), 3 ближайших,
  предложение сузить. Пусто → ближайшее событие после периода.
- **Новая команда посреди вопроса** («Что у меня сегодня?», пока ждём ответа на конфликт или
  выбор записи) выполняется как новая, вопрос снимается.
- **Поиск** (`ItemService.find`): имена и организации из запроса — жёсткий фильтр; если движок
  вернул пусто при названном имени — повтор с именем в `query`; если у движка есть явный
  лучший уровень совпадений (≤ 5), отвечаем им и добавляем «Ещё N похожих записей».
- **Длительность по умолчанию:** встреча 60 мин, демо 30 мин.

## Контракт v1.2: что используется

- `ItemRepository`: create / get / update / soft_delete / restore / list_range, журнал undo — `log_action / get_action / mark_undone`.
  Undo откатывает `state.last_action_id` (одно действие назад).
- `list_range` — интервал `[start, end)`, для дня `end` = 00:00 следующего дня; серии с rrule разворачивает домен.
- `TimeSpec.has_date` решает, «в три» это только время или дата+время. Страховка: спецификация без времени или период считаются датой.
- `Item` создаётся без `id / created_at / updated_at`.
- `DateResolver` — запасной разбор ответа на «На какое время?», если NLU не вернул `when`.
- `DialogState.last_command` (v1.2) пишется после каждого хода, кроме `clarify`. Если ход закрыл
  уточнение, туда кладётся собранная команда («встреча с Иваном, завтра 15:00»), а не голое «в три».
  После «отмена» — сама команда `REJECT`.

## Соглашения поверх контракта

1. Для `update / complete / delete` поля `slots.type`, `participants`, `organization`, `when`
   описывают **цель** («встречу с Марией в субботу»), новое время — `slots.new_when`.
2. `confirm_conflict`: в `pending.slots.when` — запрошенное время, в `new_when` — предложенный слот.
3. `awaiting="target"`: кандидаты лежат в `state.last_item_ids` по порядку показа.
4. Задачи и напоминания хранят время в `due_at`, встречи — в `starts_at/ends_at`.

## v2 (22.10)

- **Цель без даты** («Перенеси созвон с Орбитой на 16:30»): если кандидатов несколько, а ближайшая
  будущая запись одна на своё время — берём её без вопроса. Только когда в описании есть смысловые
  слова или имена («перенеси встречу на 17» по-прежнему спросит).
- **Относительный сдвиг** («на час позже», «на 30 минут раньше»): NLU отдаёт `new_when` без `start`,
  диалог считает минуты через `app.nlu.parse_shift` и двигает от времени записи (длительность сохраняется).
- **Несуществующая дата в списке** («31 ноября», `when.ambiguous`): «В ноябре 30 дней. Показать
  30 ноября или 1 декабря?» вместо подмены на «сегодня».
- **Поиск «когда последний раз»:** лучший уровень — префикс выдачи движка со score в пределах 10%
  от первого (порядок движка главнее score); внутри уровня — самая свежая/ближайшая по tense.
- **Undo создания** возвращает `items=[]`.
- **Короткие ответы со словами-паразитами:** «ну да, давай», «эм, вторую», «ээ… ну» распознаются.

## v3 (22.10, разбор живого теста)

Формат слотов от NLU — в рамках контракта v1.2 (тесты: `tests/dialog/test_live_2210.py`):

| Фраза | Что ждёт диалог |
|---|---|
| «Перенеси встречу с 23 октября на 8:00 на 24 октября 8:00» | `when` = время цели (с `has_time`), `new_when` = новое время; цель ищется в ±30 мин от `when`, слово «встречу» не нужно |
| «Перенеси последнюю задачу на один день вперёд» | `target.description="__last__"`, `type`; `new_when.text` со сдвигом (`parse_shift`) |
| «Отмени все завтрашние встречи» | `target.description="__all__"` + `type` + `when` (день или период); без `when` — все предстоящие |
| «встреча завтра в обед» | `when.ambiguous=True`, `start` (+ `end`) — окно; без `end` окно берётся по слову (утро 8–12, обед 12–14, день 12–17, вечер 18–21) |
| «в 5 или в 6», «может быть в 5, может быть в 6» | `when.ambiguous=True`, в `when.text` есть «или / либо / может быть»; варианты — из `DateResolver` по частям фразы, иначе `start`/`end` |

Поведение:
- **«Последняя»** — запись последнего действия в сессии (create/update/complete), иначе последняя из
  контекста подходящего типа, иначе ближайшая предстоящая.
- **Массовые действия** (delete / complete / update со сдвигом или датой): показ и «Да / Нет», затем
  выполнение; «отмени» откатывает весь пакет одним шагом. Пакеты хранятся в памяти процесса
  (`ItemService._batches`) — для надёжности после рестарта предложено `ActionRecord.batch_id`.
- **Рискованные действия по контексту** («эту задачу», «её»): если в контексте больше одной записи
  или `confidence < 0.85` — «Отметить выполненной «…»?» / «Перенести «…» на …?». Удаление
  подтверждается всегда.
- **Окно времени:** первый свободный слот в окне («Завтра 12:00–13:00 свободно — поставить?»), если
  окно занято — ближайший свободный после него.
- **Варианты времени:** «Во сколько поставить: 17:00 или 18:00?» с кнопками.

# Эталонный набор `golden_eval.jsonl` — формат и правила прогона

100 запросов. «Сейчас» у всех: `2026-10-21T14:00:00+03:00` (среда). Все ожидаемые id и даты вычислены скриптом по исходному CSV, а не вручную.

## Поля строки

| Поле | Что значит |
|---|---|
| `qid` | `q01`…`q100`. q01–q34 — исходный набор без изменений (в q24 добавлен только `tense: past`) |
| `category` | create, clarify, conflict, list, search, update, complete, delete, undo, smalltalk. `clarify` — строки про сценарий уточнения: сам вопрос (q08, q09, q55) и ход после него с `history` (q51, q52 — ответ на вопрос, q54 — выход «отмена»); что именно ожидается, задаёт `expected` |
| `query` | реплика пользователя |
| `history` | *(необязательно)* реплики пользователя, которые нужно прогнать в той же сессии **до** `query`. Проверяется только ответ на `query` |
| `expected` | ожидаемый результат (см. ниже) |
| `tags` | срез для метрик: `tz_original` (фраза из ТЗ), `paraphrase`, `colloquial`, `asr_noise`, `typo`, `edge_date`, `edge_time`, `synonym`, `case_mismatch`, `multi_turn`, `context`, `conflict`, `recurrence`, `empty_period`, `invalid_date`, `ambiguous_target`, `not_found`, `out_of_scope` … |

## Ключи `expected`

- `intent` — create / list / search / update / complete / delete / confirm / reject / undo / smalltalk / unknown.
- create: `type`, `title` (+ `title_accept` — допустимые варианты), `datetime` **или** `due` (дедлайн), `duration_min`, `recurrence` (RRULE), `conflicts_with_ids` (у каждой встречи; пустой список = конфликта быть не должно), `missing` (какие слоты должен уточнить ассистент).
- list: `period` [от, до] включительно, `type`, `ids` — точный набор; `nearest_id` — что предложить при пустом периоде.
- search: `relevant_ids` (+ `relevant_count`) — для Recall@5 / MRR; `answer_id` + `answer_dt` — для вопросов «когда», ответ должен назвать именно эту запись; `tense`.
- update / complete / delete: `target_id`, `new_datetime`, `requires_confirmation`; `accept` — список допустимых исходов, если запрос неоднозначен.
- `policy`, `note`, `expected_reply_like` — пояснения для человека, автоматически не сравниваются.

## Правила прогона

1. **Каждая строка — в чистой среде**: свежий импорт CSV в пустую базу, новая сессия, `FREEZE_NOW` = `now`. Записи, созданные одной строкой, в другие строки не переносятся.
2. `history` проигрывается в той же сессии перед `query`; ответы ассистента на history не оцениваются.
3. Даты сравниваются в Europe/Moscow с точностью до минуты; для `due` без времени допустимо 23:59.
4. Политики дат, на которые опирается набор: «в 3» → 15:00; «в восемь» → 08:00; «утром» 09:00, «днём» 13:00, «вечером» 19:00; день недели = ближайший будущий (сегодня, если время ещё не прошло); «следующая среда» в среду = через неделю; «до конца недели» = вс 23:59; неделя пн–вс.
5. Тип записи в CSV: «Встреча / Созвон / Демо / Провести планёрку» = meeting, «Напомнить» = reminder, остальное = task. Длительность: встреча 60 мин, демо 30 мин; задачи и напоминания внутри интервала встречи тоже считаются конфликтом.

## Как считает `run_eval.py`

Чистая среда на каждую строку, `history` проигрывается в той же сессии перед `query`, метрики и срезы по `tags` — в [`report.md`](report.md). Запуск: `make eval` (заглушки) или `make eval-real` (настоящие модули + PostgreSQL).

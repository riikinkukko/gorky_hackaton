# frontend — PWA «Помню»

React 19 + Vite + TypeScript + Tailwind 4 + PWA (vite-plugin-pwa). Работает по API из документа 03; пока бэкенда нет — на мок-API.

```bash
npm i
npm run dev:mock        # мок-API, бэкенд не нужен, «сейчас» = 21.10.2026 14:00 МСК
npm run dev             # реальный бэкенд: прокси /api, /ws, /health, /calendar → VITE_BACKEND_URL (по умолчанию :8000)
npm run build           # dist/ для Caddy
npm run build:preview   # один HTML-файл с моком — для показа без сервера
npm run seed            # пересобрать src/mock/seed.json из CSV организаторов
python3 scripts/make_icons.py  # PNG-иконки PWA из public/icon.svg (192, 512, maskable 512, apple 180)
```

## Структура

```
src/
  api/types.ts        зеркало contracts.py: Item, AssistantReply, Health, сообщения /ws/voice
  api/backend.ts      интерфейс Backend — всё, что фронт знает о сервере
  api/http.ts         реализация по контракту (fetch + WebSocket, заголовок X-User-Id)
  api/index.ts        выбор http / mock по VITE_USE_MOCK (мок — отдельный lazy-чанк)
  mock/               мок-сервер: seed из CSV (1000 записей, id совпадают с golden_eval), правила-NLU, диалог, undo
  hooks/useAssistant  диалог: текст, голос, таймауты, «Отменить», подсветка изменённого
  audio/micEngine     микрофон наготове: кольцевой буфер 400 мс (pre-roll), дозапись 400 мс (post-roll), потоковый WAV 16 кГц
  audio/pcmWorklet    AudioWorklet: микрофон → PCM 16 кГц кадрами по 20 мс
  hooks/useRecorder   React-обёртка над micEngine: состояния микрофона, разрешения, сворачивание вкладки
  hooks/useSpeaker    озвучка: аудио с сервера или speechSynthesis; выключатель
  hooks/useHealth     опрос /health, автоснятие баннера «Сервер недоступен»
  components/         Header, Login, ChatHistory, ItemCard, Composer (кнопка, режимы, ввод), AgendaPanel, Banners, DevPanel
  lib/time.ts         всё время — в Europe/Moscow независимо от браузера
```

## UX-решения

- Кнопка: «Удерживать» (по умолчанию) или «Нажать»; пробел — то же с клавиатуры, Esc — отмена, автостоп через 30 с. Слишком короткое нажатие не отправляется, а подсказывает.
- Промежуточный транскрипт виден в пузыре до отправки — ошибку распознавания видно сразу.
- Текстовый ввод есть всегда, в том числе когда микрофон недоступен.
- Под каждым ответом-действием — карточки с подсветкой «Новая / Изменена / Отмечена / Удалена» и кнопка «Отменить» (активна только у последнего действия). `suggestions` — кнопки быстрых ответов под последним сообщением.
- Состояния: нет HTTPS, микрофон запрещён / не найден / не поддерживается, сервер недоступен (баннер + переподключение каждые 5 с), долгий ответ («Думаю дольше обычного…» через 3 с, ошибка с «Повторить» через 20 с).
- Голосовой ответ перебивается новым нажатием на кнопку.

## Мок

Панель «мок» в углу: включить «Сервер недоступен» и «Долгий ответ», сбросить данные. Голос в моке: транскрипт берётся из Web Speech API браузера (Chrome/Edge), иначе подставляются фразы демо-сценария по очереди. Мок проходит все фразы ТЗ и большую часть golden_eval (q01–q31, q33, q34), но это не замена NLU чата 1.

## Поведение, которое легко сломать

- **Начало и конец фразы не теряются (web/v3).** MediaRecorder заменён на AudioWorklet: микрофон открыт, пока вкладка активна, последние 400 мс лежат в кольцевом буфере и уходят на сервер вместе с записью; после отпускания пишется ещё 400 мс. Куски по ~100 мс уходят по ходу записи — на этом держатся промежуточные транскрипты.
- **iOS Safari:** поток не держим постоянно. Микрофон открывается по `pointerdown`, «Говорите…» появляется только когда пошли реальные кадры (≈0,3 с), после записи поток живёт ещё 15 с — уточняющий ответ («в три», «да») тоже получает pre-roll. AudioContext и worklet собираются на первом жесте на странице.
- **Микрофон наготове** гаснет при сворачивании вкладки и через 5 минут без записи; рядом с кнопкой — пометка «наготове». На сервер уходит только то, что сказано с нажатой кнопкой, плюс 0,4 с до и после.
- **Обрезанное начало видно сразу:** если транскрипт начинается со слога (меньше 3 букв и это не «в», «на», «а»…), под пузырём — предупреждение.
- **Тайминги старта микрофона** — в консоль при `localStorage["pomnyu.micdebug"] = "1"`.
- **Озвучка по умолчанию включена.** Если в `reply` из WS `audio_mime = null` (`TTS_PROVIDER=browser|none`) или `/api/tts` вернул пустое тело — говорит `speechSynthesis` (ru-RU, локальный голос в приоритете). Если `audio_mime` есть, а звук не пришёл за 6 с — тоже браузер.
- **Отмена создания** убирает карточку из истории и из панели (панель перечитывается). Контракт — `items=[]`; если бэкенд всё же прислал запись, она тоже скрывается. Отмена изменения показывает запись «Как было».
- **Часы.** «Сегодня / Неделя» считаются по `now` из `/health`, чтобы совпадать с `FREEZE_NOW` сервера.

## Вход и безопасность (web/v4, API v1.3)

- **Вход — сессия, не заголовок.** Выбор демо-пользователя → `POST /api/session {"user_id"}`, сервер ставит httpOnly-cookie `pomnyu_session`. При загрузке — `GET /api/session` (401 → экран входа), «Сменить пользователя» — `DELETE /api/session`. `X-User-Id` и `?user_id=` фронт больше не шлёт; `session_id` для `/api/chat`, `/api/undo` и `/ws/voice` — из ответа `/api/session`.
- **401 любого запроса** → экран входа с «Сессия закончилась — войдите снова».
- **429** → пузырь «Слишком часто — подождите пару секунд», кнопка «Повторить» оживает по `Retry-After`. Автоповторов нет; `/api/tts` на 429 молча озвучивает браузером.
- **Мок** (`npm run dev:mock`) — тот же интерфейс входа, сессия в localStorage; в панели «мок» есть переключатель «Слишком часто (429)».
- **CSP без внешних доменов.** Шрифт Onest лежит в `public/fonts` (OFL, кириллица и латиница 400–700), AudioWorklet — отдельный файл `assets/pcm-worklet-*.js` (не `blob:`/`data:`), аудио ответа — `blob:`, WebSocket — same-origin, service worker — `'self'`. Хватает политики `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data:; media-src 'self' blob:; connect-src 'self' wss:; worker-src 'self'; manifest-src 'self'`.

## Протокол /ws/voice (контракт v1.1)

1. Открыть `/ws/voice?session_id=…` — пользователь из cookie сессии (с web/v4 `user_id` в адресе нет).
2. `{"type":"start","mime":"audio/wav"}` — во всех браузерах (с web/v3).
3. Первый бинарный кадр — заголовок WAV (PCM s16le, 16 кГц, моно, размеры 0xFFFFFFFF — потоковый) + pre-roll; дальше куски PCM по ~100 мс по ходу записи; после отпускания ещё 400 мс; затем `{"type":"end"}`. ~32 КБ/с, 30 с записи ≈ 1 МБ (лимит сервера 2 МБ).
4. Сервер: `transcript` (промежуточные и финальный) → `reply` с `audio_mime` → бинарное аудио. Фронт проставляет блобу тип из `audio_mime` (`audio/ogg` с реальным TTS, `audio/wav` на заглушке). `{"type":"error","message"}` показывается в диалоге.

## Контракт

`src/api/contracts.ts` ведёт чат 0. Фронт пользуется своими типами из `src/api/types.ts`, а `npm run check:contract` проверяет, что они совпадают с contracts.ts (тип и статус записи, action ответа, совместимость Item и AssistantReply). В обычную сборку проверка не входит.

## Docker

`Dockerfile`: сборка на node:22, раздача через nginx на :80 (`nginx.conf`: SPA-фолбэк, долгий кэш для `/assets`, без кэша для service worker). Caddy проксирует на `web:80` всё, кроме `/api`, `/ws`, `/calendar`, `/health`. Мок для стенда без бэкенда: `--build-arg VITE_USE_MOCK=1`.

## Проверка на телефоне: «Удали эту задачу» × 10

1. Открыть стенд на телефоне, войти, один раз нажать кнопку и разрешить микрофон.
2. 10 раз: зажать кнопку и **сразу** сказать «Удали эту задачу», отпустить на последнем слоге. Между попытками пауза пара секунд.
3. Считать, в скольких пузырях транскрипт начинается с «Удали». На iPhone отдельно: 10 попыток с паузой больше 15 с, начиная говорить сразу и дожидаясь «Говорите…».
4. Для разбора: `localStorage.setItem("pomnyu.micdebug","1")` в консоли (Android — chrome://inspect, iPhone — Safari → Разработка) и тайминги `[mic]`.

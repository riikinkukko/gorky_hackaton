От чата 7 (QA голоса), 22.10. Находки по устойчивости к транскриптам распознавания. Все воспроизводятся текстом,
без аудио, и уже лежат в backend/tests/e2e/test_voice_regressions.py как xfail — когда починишь,
тест покажет XPASS в pytest tests/e2e -rxX (CI от этого не падает). Напиши чату 7 номера пунктов — он снимет
маркеры (файл в его зоне).
Контекст: на 81 эталонной фразе в «чистом» виде твой разбор + диалог дают 100% golden. Ломается, когда
транскрипт написан не как эталон: числа словами (так пишут v3_rnnt/v3_ctc и SpeechKit без ITN), аббревиатуры
по буквам, падеж или буква в имени. Это ровно твоя задача «слой между GigaAM и разбором» (документ 08).

Воспроизведение для каждого пункта: make up (или uvicorn с NLU_IMPL=real DIALOG_IMPL=real, FREEZE_NOW=2026-10-21T14:00:00+03:00),
затем POST /api/chat {"text": <фраза>, "session_id": "x"} и смотреть debug.slots / action.

QA-01 · время словами после «на» в переносе не разбирается
  «перенеси созвон с орбитой на шестнадцать тридцать» → update_item, new_when=None, target.description
  съедает время → «Не нашёл запись…». То же «…в субботу на девятнадцать ноль ноль».
  С цифрами («на 16:30») работает. В создании «в пятнадцать тридцать» работает — значит, не хватает
  разбора после предлога «на».
  Починено: action=updated, «Созвон с Орбитой по презентации» → 2026-10-29 16:30; «Встреча с Марией по
  интеграции» → 2026-10-24 19:00; время не попадает в target.description.

QA-02 · «на 19» без минут в переносе теряет время
  «Перенеси встречу с Марией в субботу на 19.» → new_when = 2026-10-24T00:00 (has_time=False),
  target.description = «встречу с Марией на 19» → не найдено.
  Починено: «на 19» / «на 19 часов» = 19:00 (политика как у «в 19»), action=updated, 2026-10-24 19:00.

QA-03 · «ноль ноль» попадает в название
  «добавь встречу с командой завтра в пятнадцать ноль ноль» → дата верная, title = «Встреча с командой ноль ноль».
  Починено: title = «Встреча с командой», 2026-10-22 15:00. Проверь заодно «в девять тридцать», «в пятнадцать ноль пять».

QA-04 · аббревиатуры по буквам не приводятся к канону в названии записи
  «послезавтра в девять созвон с альфой по срм» / «…по СРМ.» → title «Созвон с альфой по срм»;
  «подготовить тэзэ для вектора» / «т з для Вектора» → «тэзэ» / «т з».
  В поиске «си ар эм» → CRM уже работает (slots.query = CRM), значит, нужно применить тот же словарь к title
  при создании и к target.description.
  Починено: «Созвон с Альфой по CRM», «Подготовить ТЗ для Вектора». Варианты: срм, цэрээм, си ар эм, тэзэ, т з, тз, кэпэ.

QA-05 · организация в именительном после «с» становится человеком
  «Когда ближайший созвон с Альфа?» → participants=["Альф"], organization=None → «Не нашёл встреч с Альфом».
  GigaAM нередко отдаёт неверный падеж редкого имени.
  Починено: organization = «Альфа», находит «Созвон с Альфой по презентации» (1 ноября 15:15).
  Правило: сначала сверка с известными организациями пользователя по лемме и по исходной форме, потом морфология.

QA-06 · искажённая организация: слот уже исправлен, а цель ищется по сырому тексту
  «Перенеси созвон с арбитой на 16:30.» → slots.organization = «Орбита» (сопоставление работает!),
  но target.description = «созвон с арбитой» → диалог не находит запись.
  Починено: action=updated, 2026-10-29 16:30. Вариант решения в твоей зоне — нормализовать сам текст
  до разбора («арбитой» → «Орбитой») или переписывать description по исправленным сущностям. Параллельно
  чат 2 получил просьбу искать цель и по slots.organization/participants.

QA-07 · имя в названии остаётся со строчной
  «напомни мне завтра в десять утра позвонить ивану» → title «Позвонить ивану» — так и сохраняется в записи.
  Починено: «Позвонить Ивану»; то же для организаций («Созвон с Альфой»). Регистр восстанавливать только для
  известных сущностей пользователя.

Распознавание, которое правилами не вылечить (класс A, для твоей таблицы asr_noise — как негативные примеры,
где нормализация НЕ должна срабатывать): «Марине» вместо «Марии», «Алёной» вместо «Еленой», «сервером»
вместо «Севером», «и вану» вместо «Ивану». Марина и сервер — настоящие слова, жёсткая замена даст ложные
срабатывания. Если делаешь нечёткое сопоставление — только когда слово не является известной сущностью/словом
словаря и расстояние ≤ 1 на основе длиной ≥ 5; «и вану» (разрыв слова) — склейка соседних токенов перед сверкой.

Как проверить себя: cd backend && pytest tests/e2e -q -rxX — твои пункты должны стать XPASS (сообщи номера чату 7),
остальные тесты e2e и tests/nlu зелёные; make eval-real не хуже 100% на эталоне.
Ветка nlu/v3. Реальные транскрипты с записей команды пришлю следующей партией — добавляй их в test_asr_noise.py.

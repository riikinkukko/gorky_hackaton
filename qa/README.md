# QA голоса (зона чата 7)

Что здесь: записи фраз, прогон записей через `/ws/voice`, классификация ошибок A/B/C/D, сравнение int8 ↔ fp32 и post-roll, отчёт. Регрессия — в `backend/tests/e2e/`, метрики распознавания — `backend/eval/asr/`.

| Файл | Что |
|---|---|
| `phrases.jsonl` | 81 фраза для записи из `golden_eval.jsonl`; `batch: 1` — первые 20 (имена, организации, время). Генерирует `tools/make_phrases.py` |
| `recorder.html` | страница записи: имя, устройство, тихо/шум, режим «как в приложении» или «чистая» → zip с файлами и `manifest.part.csv` |
| `audio/` | записи `<speaker>__<device>__<env>__<mode>__<qid>.<ext>` и `manifest.csv` (`tools/build_manifest.py`) |
| `run_voice.py` | прогон: эталон, транскрипт, WER/CER, intent/action, голос ≡ текст, проверки golden, класс ошибки |
| `compare_runs.py` | два прогона на одних файлах: ΔWER, какие ошибки исчезли и появились |
| `ab_quant.py`, `compose.qa.yml` | fp32 → int8 → int8+post-roll локально в docker compose |
| `sim/hyp_v1.csv` | симулированные транскрипты (пока нет записей): `clean`, `words` (числа словами), `asr` (типовые ошибки) |
| `runs/<имя>/` | `summary.md`, `results.csv` (`;`, открывается в Excel), `results.jsonl` |
| `live/*.jsonl` | живые реплики со стенда: транскрипт, история, ожидаемое действие, владелец, `known` — ещё не исправлено |
| `regress.py` | перепроверка после новой версии: `--merge nlu/vN dialog/vN web/vN` поверх main → «починено / регрессии / открыто», `--web` — pre/post-roll во фронте |
| `tools/import_turn_log.py` | строки `turn` из лога стенда → черновик `live/drafts/<дата>.jsonl` |
| `prompts/` | готовые промпты владельцам по находкам |
| `REPORT.md` | итог: метрики, A/B/C/D, топ ошибок |

## 1. Записать

1. `python -m http.server 8765 -d qa`, открыть `http://localhost:8765/recorder.html` (микрофон работает только на `localhost` или HTTPS).
2. Ввести имя латиницей, выбрать устройство и условия. Режим по умолчанию — **«как в приложении»**: микрофон открывается при нажатии и закрывается при отпускании, как во фронте. Так в записи остаются те же обрезки начала и конца, что у жюри (класс D).
3. Зажать кнопку или пробел, сказать фразу, отпустить. Партия 1 — 20 фраз, около 3 минут. Затем «Скачать zip».
4. Телефон: страница по `http://` с телефона микрофон не получит. Варианты: (а) открыть рекордер на ноутбуке с телефонной гарнитурой; (б) записать фразы диктофоном телефона и назвать файлы по шаблону с `mode = memo`, например `masha__phone__noise__memo__q10.m4a`.
5. Распаковать в `qa/audio/`, затем `python qa/tools/build_manifest.py`.

Цель — 60–80 фраз от 3+ человек: ноутбук и телефон, тихо и с шумом (музыка или разговор на фоне).

## 2. Прогнать

Локально (docker compose, настоящий GigaAM, «сейчас» = 21.10.2026 14:00 — работают проверки golden):

```bash
GIGAAM_QUANTIZE=int8 TTS_MODELS=0 docker compose -f docker-compose.yml -f docker-compose.override.yml -f qa/compose.qa.yml up -d --build
cd backend && .venv/bin/python ../qa/run_voice.py --base http://localhost:8080 --name local-int8
```

Стенд — осторожно, по одной фразе:

```bash
.venv/bin/python ../qa/run_voice.py --base https://voice.planimetrika.online --stand --qids q19,q24,q78 --name stand-check
```

`--stand` ставит паузу ≥ 3 с, отправляет чанки в реальном времени, берёт не больше 25 строк и по умолчанию только читающие фразы (list/search). Пользователь 1 на стенде — демо для жюри, поэтому изменяющие фразы идут только с `--allow-writes`, и каждая откатывается через `/api/undo`. На стенде «сейчас» настоящее, проверки golden выключаются, остаётся «голос ≡ текст».

Без моделей (CI, ноутбук без Docker): `STT_PROVIDER=fake`, а вместо аудио — готовые транскрипты:

```bash
.venv/bin/python ../qa/run_voice.py --base http://localhost:8000 --hyp-csv ../qa/sim/hyp_v1.csv --name sim-v1
```

int8 ↔ fp32 и post-roll одной командой: `python qa/ab_quant.py` (сборка дважды, ≈ 2 ГБ RAM на квантовании).

## 3. Как считается

Для каждого файла `run_voice.py` делает два хода:

- **текст**: эталонная фраза из `golden_eval` → `POST /api/chat` в новой сессии. Это поведение при идеальном распознавании, кэшируется по qid;
- **голос**: файл → `/ws/voice` (`start{mime}` → чанки по 250 мс → `end`), как шлёт фронт.

Изменения откатываются через `/api/undo`, поэтому база не засоряется.

- **Голос ≡ текст** — совпадают intent, action и записи в ответе (id из CSV; для новых — тип, название без регистра, время до минуты).
- **golden** — `eval.run_eval.score`, те же проверки, что в `make eval`. Включаются, только если на сервере `now` = `2026-10-21T14:00+03:00`.
- **WER/CER** — `backend/eval/asr/wer.py`: нормализация чата 4 (`normalize_for_wer`) плюс «15 00» → «15:00».
- **Сущности** — доля имён и организаций, узнаваемых по корню из 4 букв.

| Класс | Условие | Владелец |
|---|---|---|
| **D** запись/фронт | пустой транскрипт или «не расслышал»; голос ≠ текст, и все расхождения — потерянные слова в начале или конце; сервер получил аудио короче файла (> 0,3 с) | чат 5, чат 4 |
| **A** распознавание | голос ≠ текст, транскрипт отличается от эталона | чат 4; если ошибку можно исправить по словарю сущностей — чат 1 |
| **B** понимание | голос ≠ текст при верном транскрипте (другая форма: «пятнадцать ноль ноль», «срм»), или текстовый эталон не прошёл проверки intent/date/slots | чат 1 |
| **C** диалог/ответ | intent и слоты верные, но список, поиск, конфликт или правка не те | чат 2, чат 3 |

Слова «ноль», «э», «ну» при классификации не считаются ошибкой транскрипта.

## 4. Регрессия

Два набора, оба — транскрипт → `/ws/voice` (кадр `text:` для заглушки STT) → настоящие NLU и диалог на правилах:

- `backend/tests/e2e/test_voice_regressions.py` — типовые ошибки распознавания (QA-01…07), «сейчас» = эталон (21.10 14:00);
- `backend/tests/e2e/test_live.py` — живые реплики из `qa/live/*.jsonl`. Каждая идёт в свежем приложении с историей сессии, «сейчас» = вечер теста (22.10 20:00), пользователь 2. Кроме intent/action проверяется снимок записей до и после: для обрезанных фраз (класс D) важно, что **ничего не изменилось**.

Открытые находки помечены `xfail` / `known` (нестрогий — починка в чужой ветке не роняет CI).

**Хранилище.** По умолчанию — память с CSV. Чтобы проверить на PostgreSQL, задайте `QA_LIVE_DATABASE_URL=postgresql+psycopg://…/qa_live`: база отдельная, с «qa» в имени, с расширениями vector и pg_trgm. Миграции применятся сами, а перед каждой репликой записи её пользователя (2 или 3) стираются. В `regress.py` — флаг `--pg URL`.

**После каждой новой версии nlu / dialog / web:**

```bash
cd backend
.venv/bin/python ../qa/regress.py --merge nlu/v4                    # одна ветка поверх main
.venv/bin/python ../qa/regress.py --merge nlu/v4 dialog/v3 web/v3   # вместе, как будет после мержа
.venv/bin/python ../qa/regress.py --update-known                     # после мержа в main: снять known
```

Отчёт — `qa/runs/regress-<ветки>.md`. Код возврата 1 означает регрессию: реплика без `known` перестала проходить или упал e2e.

**Лог стенда.** Логи хранятся в приватном репозитории `riikinkukko/gorky_logs` (`turns/ГГГГ-ММ-ДД.log`). Набор за 23.10 собирает `python qa/tools/build_live_2310.py ../gorky_logs/turns/2026-10-23.log`: сессии проигрываются целиком, а пометки `known` при пересборке сохраняются. Пометка `known_on: ["memory"]` значит, что реплика падает только на заглушке поиска в памяти; на PostgreSQL она должна проходить.

**Новый живой тест:** выгрузить строки `turn` из лога API на сервере, затем `python qa/tools/import_turn_log.py turns.txt`. Получится черновик с историей сессий и ответами стенда. Ошибочные реплики дополнить полем `expect`, класс и владелец — и перенести в `qa/live/<дата>.jsonl`.

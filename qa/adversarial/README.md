# Состязательные реплики (зона чата 9)

Реплики, на которых ассистент может ошибиться, — так, как люди говорят голосом. Пять задач, по файлу на каждую:

| Файл | Задача | Что проверяем |
|---|---|---|
| `record_task.jsonl` | записать дело | задача / напоминание: дата, время, название без мусора |
| `record_meeting.jsonl` | записать встречу | тип `meeting`, время обязательно (иначе уточнение), конфликты |
| `upcoming.jsonl` | узнать, что впереди | список за период, «ближайшая …» |
| `find_old.jsonl` | найти старое | поиск прошедших записей, список за прошлый период |
| `correct.jsonl` | поправить | перенос, сдвиг, удаление (с подтверждением), «готово», повтор, «её»/«его» из контекста |

Сводка по осям — `SUMMARY.md`. Файлы собирает `build.py` из `scenarios/*.py`; руками `.jsonl` не правим:

```bash
python qa/adversarial/build.py          # CSV берётся из data/
```

## Формат строки

```json
{"id": "rm-009", "task": "record_meeting", "axis": "word_order",
 "turns": ["с Маяком созвон двадцать девятого в шестнадцать"],
 "freeze_now": "2026-10-23T15:00:00+03:00",
 "expect": {"intent": "create_item", "action": ["created", "conflict"], "type": "meeting",
            "date": "2026-10-29", "time": "16:00", "title_contains": ["маяк"]},
 "note": "пересекается с CSV: 29.10 15:30 Созвон с Орбитой по презентации"}
```

- `turns` — реплики одной сессии; оценивается ответ на **последнюю**, остальные — история (как `history` в golden).
- **Среда — как у golden**: свежий импорт CSV, пользователь 1, новая сессия, `X-Freeze-Now` = `freeze_now` (пт 23.10.2026 15:00 МСК).
- `freeze_now` у каждой строки свой: у оси `stand_live` — момент реплики на стенде (МСК), у остальных — пт 23.10 15:00.
- В `expect` только то, что предсказуемо однозначно. Список значений (`action`, `intent`) — любой из вариантов допустим.

| Ключ | Как сравнивать |
|---|---|
| `intent` | `Command.intent` (`debug.intent`) |
| `action` | `AssistantReply.action` |
| `type` | тип созданной / изменённой записи |
| `date`, `time` | у записи из ответа: `starts_at` или `due_at` в Europe/Moscow; для дедлайна без времени допустимо 23:59. У `list_items` — `date` = день, `period` = [от, до] включительно |
| `duration_min` | `ends_at − starts_at` |
| `title_contains` | корни без регистра; хотя бы одна запись в ответе содержит все |
| `title_not` | ни одна созданная запись не содержит этих слов (паразиты, мат, обрезки) |
| `tense` | `slots.tense` |
| `must_not` | запрещённые операции: `create` → action `created` или intent `create_item`; `update` → `updated`; `delete` → `deleted`; `complete` → `completed`; `undo` → `undone`; `search` → `found`; `list` → `listed` |
| `forbid_at` | суффиксы времени, которых не должно быть у созданной записи (`"T15:00"`) — как в `qa/live` |
| `min_items`, `max_items` | сколько записей в ответе (в уточнении — сколько названо) — как в `qa/live` |
| `reply_has`, `reply_not` | в тексте ответа есть хотя бы одна из подстрок / нет ни одной — как в `qa/live` |

## Что вычисляет `build.py`, а не автор

- **Конфликты.** Если новая (или перенесённая) запись пересекается с записью CSV по правилам golden (встреча 60 мин, демо 30, задача внутри встречи — тоже конфликт), к `action` добавляется `conflict`, а в `note` — с чем.
- **Цель правки.** В `correct` цель ищется в будущих записях CSV по корням; ожидается ближайшая (как q89). Если в ближайшие 30 дней кандидатов несколько — допустим `clarify` (как q91). Новое время при переносе «только даты» и при сдвиге («на час позже») считается от времени цели.
- **Наличие данных.** Корни из `title_contains` у поиска старого проверяются по прошлым записям CSV, у «впереди» — по будущим. Синонимы как в CSV: деньги → «бюджет», КП → «коммерческое предложение», ТЗ → «техническое задание».

- **Конфликт.** При `action = conflict` в `items` ответа — существующие записи, с которыми пересеклась новая, поэтому `type`, `date`, `time`, `title_*`, `duration_min` относятся к записи, которая была бы создана, и при конфликте не проверяются.

## Оси

`word_order` порядок слов («в часов пять») · `colloquial_time` «полчетвёртого», «к обеду», «после праздников», «через пару дней» · `asr_cut` потерянный первый слог («помни», «реноси»), без пунктуации, нижний регистр · `numbers_words` числа словами · `fillers_slang` паразиты, сленг, мат · `self_correction` «в среду, ой нет, в четверг» · `two_commands` две команды в одной фразе · `context` местоимения, «а на завтра?», ответы на уточнение · `tense` прошлое/будущее («старую», «та, что была», «было … завтра») · `polite_indirect` «не могли бы вы…», «надо бы не забыть…», «напомни, что у меня…» · `nonsense` бессмыслица и не по теме — ожидается переспрос или отказ, а не запись; если у фразы форма команды ассистента («покажи котиков», «найди мне девушку»), честное «не нашёл» тоже допустимо · `stand_live` реальные реплики тестировщиков со стенда (`riikinkukko/gorky_logs`, `turns/*.log`), по одной на тип ошибки из `qa/live` (QA-xx в `note`); история достроена только там, где без неё реплику не воспроизвести (помечено в `note`).

## Политики, на которые опираются ожидания

Из `golden_eval_format.md`: «в 3» → 15:00, «в восемь» → 08:00 (1–7 без «утра» — после полудня); утром 09:00, днём 13:00, вечером 19:00; день недели — ближайший будущий (сегодня, если время не прошло); «следующая пятница» в пятницу — через неделю; «до конца недели» — вс 23:59; неделя пн–вс. Удаление — только с подтверждением.

Где политики нет, время или дату **не проверяем**: «в обед» / «к обеду» (в коде 12:00, в `live` L32 ждут 13:00), «после праздников», «в начале ноября», «в пятницу» без времени, когда сегодня пятница, «ближе к вечеру».

Всё поведение — из ТЗ (`Testovoe_zadanie…pdf`): создание, список, поиск, правка, удаление, «выполнено», конфликты, повторы, контекст, уточнения. Две записи из одной фразы и отмена (undo) — из `live` и контракта; там, где ТЗ молчит, допустимы оба исхода (`["created", "clarify"]`).

## Как решаем спорные ожидания (v2)

1. Ожидание однозначно, только если его даёт ТЗ, политика golden или явная команда в реплике. Иначе — список допустимых исходов, а поля, которые у исходов расходятся, не заполняем.
2. Реплика без глагола-команды («было бы удобнее встретиться с Марией в воскресенье», «встреча 14 января с Марией») — это и создание, и правка/поиск: `intent` — список, `action` — то, что верно для обоих (обычно `clarify` или само действие), запрещено только явно вредное (создать встречу без времени).
3. Нет времени у встречи или время размыто («ближе к вечеру», «после праздников») — переспрос допустим (ТЗ: «может задать уточняющий вопрос»), `none` с переспросом тоже.
4. Явная самопоправка («ой нет», «то есть», «точнее») — не неоднозначность: ждём исправленное значение, переспрос «15:00 или 16:00?» — ошибка.
5. Если слово типа обрезано распознаванием («речу», «звон с», «ланёрку»), тип не проверяем — только мусор в названии.

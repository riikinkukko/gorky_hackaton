# «Помню» — голосовой ассистент для задач, напоминаний и встреч

Говорите как обычно: «напомни завтра в 10 позвонить Ивану», «что у меня на неделе?», «когда я встречался с Иваном?». Ассистент поймёт, сохранит, найдёт и ответит голосом.

**🔗 Прототип:** https://voice.planimetrika.online · **📅 Календарь:** https://voice.planimetrika.online/calendar/demo.ics · **📊 Качество:** [метрики](#качество)

На стенде у демо-пользователя 1 загружены 1000 событий организаторов (2024–2027 годы), пользователи 2 и 3 начинают с пустого списка. Вход — кнопкой выбора пользователя на странице.

## Быстрый старт

Нужны Docker 24+ и Docker Compose v2.

```bash
git clone https://github.com/riikinkukko/gorky_hackaton.git && cd gorky_hackaton
cp .env.example .env
make up                       # api, web, db (PostgreSQL + pgvector), caddy
open http://localhost:8080    # Swagger: http://localhost:8080/docs
```

Миграции и импорт CSV организаторов в пользователя 1 выполняются при старте API. Вручную — `make migrate` и `make seed`.

> ⚠ Браузер даёт доступ к микрофону только по **HTTPS** или на `localhost`.
>
> Голосовые модели собираются в образ при `VOICE_MODELS=1`. Профили по памяти — в `.env.example`: полный (≈2 ГБ), для сервера 4 ГБ (GigaAM int8 + озвучка браузером, ≈1,1 ГБ) и без моделей (SpeechKit).

### Разработка без Docker

```bash
make install      # venv + зависимости бэкенда и фронта
make dev-api      # uvicorn :8000
make dev-web      # vite :5173, проксирует /api и /ws на :8000
make check        # lint + test + eval
```

## Как это работает

```
Браузер (React PWA) ──аудио/текст──▶ nginx/Caddy (HTTPS) ──▶ FastAPI (REST + WebSocket)
                                                               │
  voice/   ffmpeg → STT: GigaAM | SpeechKit | Whisper   TTS: браузер | Silero | SpeechKit
                                                               │ текст
  nlu/     нормализация транскрипта → ответ на уточнение → правила → LLM (function calling)
           → DateResolver (даты считает код)
                                                               │ Command (Pydantic)
  dialog/  уточнения, контекст «её», выбор из нескольких, подтверждения, «Отменить»
  domain/  конфликты и свободный слот · повторы (RRULE) · тексты ответов
  storage/ PostgreSQL + pgvector · поиск: кандидаты из полнотекста, триграмм и векторов → ранжирование по смыслу
```

ТЗ просит понятно разделить четыре части — голос, LLM, бизнес-логику и хранение данных. У нас это отдельные модули за общими интерфейсами:

| Часть по ТЗ | Модуль | Как подменяется |
|---|---|---|
| Работа с голосом | [`voice/`](backend/app/voice/README.md) | `STT_PROVIDER`, `TTS_PROVIDER` |
| LLM | [`nlu/llm/`](backend/app/nlu/README.md) внутри `nlu/` | `LLM_PROVIDER` (вплоть до `rules` — без LLM) |
| Бизнес-логика | [`dialog/`](backend/app/dialog/README.md) + `domain/` | `DIALOG_IMPL` |
| Хранение данных | [`storage/`](backend/app/storage/README.md) | `STORAGE_IMPL` |

**Главный принцип: LLM только понимает запрос.** Модель возвращает намерение и слоты по строгой схеме. Даты, конфликты, повторы, поиск и тексты ответов считает обычный тестируемый код. Сначала работают правила (≈1 мс, без сети); LLM подключается, только если их уверенность ниже 0,85. Поэтому все метрики ниже получены **без LLM**, а на стенде GigaChat дополнительно подстраховывает свободные формулировки.

Слои общаются только через интерфейсы из [`backend/app/contracts.py`](backend/app/contracts.py) (история — [`docs/CONTRACT.md`](docs/CONTRACT.md)). Реализацию выбирает [`backend/app/container.py`](backend/app/container.py) по переменным окружения.

### Данные организаторов

CSV из 1000 строк (`id, date, time, text`) импортируется в пользователя 1; id записей совпадают с CSV.

- **Нет типа, статуса и даты создания.** Тип выводится по шаблону текста: 761 задача, 186 встреч, 53 напоминания. Статус импортированных записей — `unknown`: «выполнено» не выдумываем.
- **Сломанные падежи** («Позвонить Иваном», «Обсудить договору с Алексеем»). Исправлено 313 заголовков. Люди, компании и темы вынесены в отдельные поля в начальной форме, исходный текст сохранён в `title_original`.
- **Даты с 2024 по 2027 год.** Прошлое и будущее различаются: «была», «старую», «прошлую» ищут только в прошлом, «следующая» — только в будущем.

## API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/session` | `{ "user_id" }` → вход демо-пользователя (cookie); `GET` — кто вошёл, `DELETE` — выход |
| `POST` | `/api/chat` | `{ "text", "session_id" }` → `AssistantReply` (текст, действие, записи, кнопки) |
| `WS` | `/ws/voice?session_id=` | аудио → транскрипт, ответ, озвучка (протокол — [`voice/README.md`](backend/app/voice/README.md)) |
| `POST` | `/api/tts` | `{ "text" }` → аудио |
| `GET` | `/api/items?from=&to=&type=` | записи за период |
| `POST` | `/api/undo` | `{ "session_id" }` → отмена последнего действия |
| `GET` | `/calendar/{token}.ics` | ICS-фид для подписки (`demo` → пользователь 1) |
| `GET` | `/health` | состояние БД, LLM, STT, TTS, подключённые реализации, «сейчас» |

Пользователь — подписанная cookie `pomnyu_session` (HttpOnly, Secure, SameSite=Strict). В prod без неё — 401; вне prod для тестов и eval работает заголовок `X-User-Id`. Частота запросов ограничена (429 + `Retry-After`). Swagger — `/docs`.

## Качество

Мы проверяем ассистента на четырёх уровнях — от фраз из ТЗ до живых людей, которые проект не видели.

```bash

make eval-real     # эталонный набор: настоящие модули + PostgreSQL → backend/eval/report.md
make adversarial   # каверзные реплики + оракулы (≈10 мин)
```

### 2. Каверзные реплики — 583 сценария

Эталонный набор составляли мы сами, поэтому отдельно собран набор фраз, на которых ассистент *может* ошибиться: [`qa/adversarial/`](qa/adversarial/README.md). Пять задач пользователя из ТЗ × 12 осей: порядок слов, разговорное время, обрезки распознавания, числа словами, паразиты и мат, самопоправки, вежливые формы, прошлое и будущее, две команды сразу, контекст, бессмыслица, реальные фразы со стенда.

Кроме ожиданий по каждой фразе, прогон проверяет **оракулы** — правила, верные для любой фразы: в названии записи нет мусора (слов времени, местоимений, мата), ответ называет сохранённое время, «прошлое» не возвращает будущее, нет ошибок сервера. Прогон — на каждый пуш в `main` и каждое утро (workflow Adversarial), без LLM, то есть это нижняя граница.

| Задача пользователя | 24.10, утро | 24.10, после исправлений |
|---|---:|---:|
| Записать дело | 58% | 83% |
| Записать встречу | 41% | 97% |
| Узнать, что впереди | 40% | 98% |
| Найти старое | 71% | 87% |
| Поправить | 38% | 94% |
| **Всего** | **50%** | **92%** |

Проверка на подгонку: на 30 новых фразах, которых не видел ни один разработчик, — 25 / 30. Динамика — [`qa/adversarial/BASELINE.md`](qa/adversarial/BASELINE.md).

### 3. Живые логи стенда

Каждая реплика стенда (фраза, распознанное намерение, ответ; почты и номера маскируются) раз в час уходит в отдельный приватный репозиторий. Каждое утро логи разбираются: неудачные фразы становятся тестами в [`qa/live/`](qa/live), исправление проверяется этим же тестом.

### 4. Тесты на людях

Команда и знакомые тестировали стенд голосом с телефонов 22, 23 и 28 октября — 91 реплика в живых сессиях. Каждая неудачная фраза разобрана и стала тестом (`qa/live/`, `qa/sessions/long.jsonl`). Для слепого теста — люди, которые проект не видели, получают карточки-ситуации без названий команд и говорят своими словами, ведущий молчит — подготовлен протокол `qa/blind/` (карточки, лист ведущего, подсчёт `summarize.py`).

### CI

На каждый коммит: ruff, mypy, pytest с PostgreSQL, эталонный набор, сборка Docker, проверка секретов (gitleaks) и уязвимых зависимостей. Зелёный CI в `main` → автодеплой → смоук-тест стенда.

## Деплой

VPS + Docker Compose + Caddy с автоматическим HTTPS (Let's Encrypt):

```bash
git clone https://github.com/riikinkukko/gorky_hackaton.git /opt/gorky_code
sudo bash /opt/gorky_code/deploy/setup-vps.sh
nano /opt/gorky_code/.env                           # DOMAIN, ACME_EMAIL, POSTGRES_PASSWORD, SESSION_SECRET
sudo -u deploy make -C /opt/gorky_code prod-up
make -C /opt/gorky_code smoke URL=https://$DOMAIN
```

Сервер уже занят другим приложением — `make shared-up`: стек слушает только `127.0.0.1:8080`, HTTPS делает существующий nginx или Caddy (конфиги — `deploy/shared/`), у контейнеров лимиты памяти и процессора. Так устроен наш стенд. Без своего домена подойдёт `<ip-через-дефисы>.sslip.io`. Автодеплой после зелёного CI в `main` — `.github/workflows/deploy.yml`; ключ деплоя на сервере может только запустить деплой.

**Безопасность.** Внутренний аудит ([`docs/security/REPORT.md`](docs/security/REPORT.md)) нашёл 19 пунктов, все закрыты в коде: вход через подписанную cookie, проверка Origin у WebSocket, лимиты частоты в приложении и в nginx, ограничения на размер и длительность аудио, строгая CSP, контейнеры без root, экранирование ICS, отдельный пользователь для деплоя.

## Принятые решения

- **LLM не вычисляет даты.** Модель извлекает фразу времени, дату считает код. Политики: «в 3» → 15:00, «в восемь» → 08:00; «утром» — 09:00, «вечером» — 19:00; день недели — ближайший будущий; неделя — пн–вс; задача с датой, но без времени — 10:00 с предложением сменить время.
- **Абсолютная дата в каждом подтверждении.** Ошибку видно сразу; исправить можно фразой («нет, в 11») или кнопкой «Отменить».
- **Сначала правила, потом LLM.** Частые запросы закрываются правилами за миллисекунды и без затрат на LLM; ассистент работает и без сети к LLM.
- **Распознавание на своём сервере.** GigaAM — сильный открытый ASR для русского: голос не уходит во внешние сервисы, нет оплаты за минуту. Озвучка на стенде — голосом браузера, чтобы не занимать память сервера.
- **Одна база для всего.** PostgreSQL + pgvector: точные фильтры (дата, человек, тип), полнотекст и векторы в одном запросе и в одной транзакции.
- **Мягкое удаление и журнал действий** — основа для «Отменить».
- **Заглушки и контракт с первого дня.** Каждый модуль подменяется через `.env`, поэтому направления разрабатывались параллельно.
- **Проверка не только «своими» фразами.** Каверзные реплики, живые логи и слепой тест — потому что эталонный набор, составленный командой, слишком лёгок для своей же системы.

## Что улучшили бы при наличии времени

- Замерить WER распознавания и задержку голосового ответа на стенде (инструмент готов) и провести слепой тест на людях со стороны.
- Контекст диалога на продолжениях без явной команды («а давай лучше в субботу»), нейросетевые эмбеддинги для поиска на более мощном сервере.
- Двусторонняя синхронизация с календарём (CalDAV), доставка напоминаний через Telegram или MAX.
- Утренняя сводка и подготовка к встрече по истории.
- Развёртывание в контуре заказчика с локальной LLM; интеграции с CRM и СЭД.
